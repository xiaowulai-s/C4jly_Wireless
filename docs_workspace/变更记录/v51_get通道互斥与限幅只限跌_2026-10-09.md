## 一、P1-C · `get` 应答通道串扰 → 改为互斥

### 根因

`tjc_get()` 的回包**不带"我是在回哪个请求"的身份**，而阈值回读与 RTC 校时都调它。
原 `hmi_get_response()`（`main.c:209`）只靠优先级猜：

```c
if (g_thr_wait) { ... thr_apply_hi_val(v); return; }   /* 阈值优先 */
if (g_sync_st >= 2u || !g_rtc_wait) return;            /* 否则当 RTC */
```

**串扰场景**：上电校时持续数秒（还叠着 `main.c:374-377` 三次 `HAL_Delay` 共 3.5 s 的串口阻塞期），
期间在设置页按阈值键盘 → 两个 `get` 的应答都会被判给"先来的 `g_thr_wait`" ⇒
**RTC 读数（如 `rY_i` = 2026）被当成高报阈值 → 钳到 `THR_HI_MAX=1500` 并落盘**。

### 修法：单一所有权 `g_get_busy`（6 处）

| # | 位置 | 改动 |
|---|---|---|
| C-1 | 变量区 | 新增 `static volatile uint8_t g_get_busy`（**通道归属**，区别于 `g_thr_wait` = "阈值已发出 get"） |
| C-2 | `hmi_get_response()` | 判据从 `g_thr_wait` 改为 **`g_get_busy`**，收到即清 |
| C-3 | `rtc_time_sync_poll()` | `if (g_get_busy) return;` —— 阈值占用时**让出通道**（校时会自动重试，不丢） |
| C-4 | `thr_hi_readback_poll()` | `if (g_rtc_wait) return;` —— RTC 占用时让出；发出 get 时**置 `g_get_busy = 1`** |
| C-5 | 同上·放弃分支 | `g_thr_try >= 5` 放弃时**必须清 `g_get_busy`**，否则 RTC 永久堵死 |
| C-6 | 同上·超时分支 | 应答超时（500 ms）时清 `g_get_busy` |

★ **C-5/C-6 是本次的关键细节**：加互斥容易漏掉"退出路径要释放所有权"，一旦漏了 RTC 校时会永久卡住（表现为时间戳退化到 1970）。两处退出路径都补了清理。

## 二、P1-E · `BAT_SLEW_LIMIT` 双向限幅 → 只限跌

### 根因

```c
if (d >  BAT_SLEW_LIMIT) g_batt_pct = last_pct + BAT_SLEW_LIMIT;   /* 限涨 */
if (d < -BAT_SLEW_LIMIT) g_batt_pct = last_pct - BAT_SLEW_LIMIT;   /* 限跌 */
```

限幅的**初衷是抑制报警喇叭拉低电压**造成的骤降（实测 `78% → 22%`），**只需要"限跌"**。
双向限幅把充电时的**上升沿也压住** ⇒ 显示比真实值偏低最多 **3%**，且要靠滞回门槛（0.5+0.6 = 1.1%/格）慢慢爬。

### 修法（1 行）

```c
if (last_pct >= 0 && (g_batt_pct - last_pct) < -BAT_SLEW_LIMIT)
  g_batt_pct = last_pct - BAT_SLEW_LIMIT;   /* 只限跌 */
```

⚠️ **代价（已知取舍）**：充电时电量显示的**跳变会变快**（不再被 3%/poll 的上限压住）。
考虑到充电时 `SS34` 压降波动本来就会让电压抖，这属于"真实反映"，我判断可接受。**若真机觉得跳得刺眼，再议加"限涨但放宽到 5%"。**

