# v43 变更与验证记录：正常态保持"屏端原色"（色带与浓度大字不再变绿）

> 2026-09-30。基线：屏 `C4F7N_v8.HMI`（md5 `ad68fbd6`，**本次未改动**）+ 固件 v42（md5 `3554eaa9`）。
> 承接 v42（顶栏色带由 `pco` 改推 `bco`，**已真机验证变色**）。

## 1. 需求与关键约束

**需求**（用户）：**第一档（正常态，`g_alarm == 0`）不要修改顶栏状态指示色带与浓度大字 `cc` 的颜色，保持屏端原色。**

**约束 —— 不能简单地"不推"**：

| 步骤 | 若"正常态不推" | 结果 |
|---|---|---|
| 上电 / 进页 | 屏端按页面初值绘制 | 显示屏端原色 ✓ |
| 报警 | 固件推橙/红 | 变橙/红 ✓ |
| **报警解除** | **固件不推** | **屏端保留上一步的橙/红** ❌ 颜色卡住 |

⇒ 正确做法：**正常态推"等于屏端初值"的颜色常量** —— 效果 = 保持屏端原色，且能从报警色**回落**到原色。

## 5. 待真机验证（4 项）

1. **正常态**：顶栏色带 = 屏端原样的**深灰蓝**、浓度大字 = **浅灰白**（**都不再是绿色**）
2. **报警时**：色带与大字**同时**变橙（1 级）
3. **高报 / 超量程**：变红（2 级）
4. **报警解除后回落到屏端原色**（不是卡在橙/红）—— ★ 这条正是"不能简单跳过推送"的原因，重点验

## 6. 注意

- ⚠️ **`C_STRIP_IDLE` / `C_CONC_IDLE` 的值取自屏工程编辑器初值**。日后若在编辑器里改了 `dvr` 的 `bco` 或 `cc` 的 `pco`，**必须同步修改这两个常量**，否则"报警解除回落"时会跳成旧颜色。
- ⚠️ 若希望"改屏色不必动固件"，可改走"屏端全局变量 + 页 `load` 自恢复"方案（需动屏包脚本，本次未采用）。
