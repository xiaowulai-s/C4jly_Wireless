# v6（fix14）变更与验证记录 — 修「阈值字段进页显示 500」

> 2026-09-23 ｜ 基线：屏 `C4F7N_v5.HMI`（编辑器重存版，md5 `fff2fdb9`）/ 固件 `v22`（md5 `d406f940`）
> 触发：真机现象「点 `h` 弹数字键盘 → 输入 1000 → 生效；但字段仍显示 500；点一次 `+` → 变 1050」

## 1. 根因（结论 + 证据）

**`h` 是本工程唯一「屏端零自刷新」的镜像控件。**

| 环节 | 事实 | 出处 |
|---|---|---|
| 屏上能显示 500 的对象 | 全 5 页**只有 1 个**：`5.pa` `h`（`type=54 id=8 val=500 key=2 vscope=1`） | `_thr_find500.js` |
| `h` 的屏端刷新 | **零**：无 `codesload`、无 `codestimer` 写它；设置页 load 19 行只刷时间/按钮文案，`tm0` 12 行只刷时间 | `_thr_page5.js` |
| 固件写 `h` 的地方 | **全固件 1 处**：`main.c:230 app_apply_threshold()` | `_thr_diag.js` |
| 推送时机 | ① 值变化（`g_thr_dirty`，主循环）；② 进设置页（`hmi_on_page_enter(1)`，**ISR 内、且在 `page 2` 之前**） | 同上 |
| 键盘返回路径 | `page loadpageid.val` **不发 0x41** → 该路径上固件没有任何刷新 | `_thr_pageids.js` |
| 回读机制本身 | `get h.val` → `hmi_get_feed` 状态机**正确**（吃满 4 数据字节 + 2 帧尾 0xFF） | `hmi_get.c` |
| `+` 按钮 | 只发 `printh 02`，屏端不自增 → 得 1050 ⇒ `PP.thr_hi` 当时确为 1000 ⇒ **键盘值确实进了固件** | `_thr_page5.js` |

**TJC 语义**：进页时对象按「**页面里存的初值**」绘制。官方（本项目已记录）：刷新代码必须写进
「页面前初始化事件 + 定时器」两处，**否则进页会显示旧值** —— 本项目时间字段踩过同一个坑（fix11 才补）。

`h` 页面里存的初值 = **500** → **每次进设置页（含键盘返回 `page loadpageid.val`）都画成 500**。
其余镜像（浓度/电量/探泵状态/时间）都是**每 250 ms 无条件推**或 **load+定时器刷**，被覆盖后能自愈；
`h` 不能，一错就永久停在 500。

**为什么 `+` 立刻显示 1050**：0x02 走 `g_thr_dirty` → 主循环在**页面显示完成之后**才 `tjc_set_val("h",1050)`，
时机正确 → 看得见。

## 2. 修法（三方闭环）

```
固件 ──写全局变量 thr=1000──▶ 屏端 Program.s 的 int thr
                                  ▲
屏设置页 load:  若 h.val≠500 则 thr=h.val（采收键盘刚写入的值）→ 再 h.val=thr（立即用权威值绘制）
屏设置页 tm0:   h.val=thr（周期跟随）
键盘 OK:        写入对象 h.val 后，先把值写进 thr，再 printh 11（通知固件回读）、返回设置页
```

时序（键盘改值 1000）：
1. 键盘 OK：`h.val=1000` → `thr=1000` → `printh 11` → `page 2`
2. 设置页 load：`h.val(1000)≠500` → `thr=1000` → `h.val=thr`（**显示立即正确**）
3. 固件收 0x11 → 主循环 `get h.val` 得 1000 → `PP.thr_hi=1000` → 推 `h.val` 与 `thr`
4. `tm0` 每 300 ms 保持 `h.val=thr`

时序（普通进设置页）：
1. load：`h.val==500`（页面初值）→ **不采收** → `h.val=thr`（**直接显示权威值，无闪变**）
2. nav 按钮发的 0x41 → 主循环 `app_apply_threshold()` 再推一次（兜底：开机那次推送可能因屏未启动而丢失）

## 5. 顺带修掉 / 更正的事

- **✅ 修掉隐患**：`thr_apply_hi_val()` 原来每次回读成功都 `thr_commit()` → 落盘（**值没变也写 flash**）。
  本版加了值变化守卫（屏幕现在每次进设置页都会回读一次，不守卫会写坏扇区 0）。
- **✅ 修掉隐患**：`hmi_on_page_enter()` 里的 `app_apply_threshold()` 是 **ISR 内阻塞发串口**（13 ms/帧，与页面重绘竞态）
  → 改为置标志、主循环执行。
- **★ 认知更正 1**：`h.key` 的 N **不是页 ID，而是「键盘风格」选择项**（官方 QA19）。
  **编辑器保存时恒写回 `2`**（= keybdB 风格）。我此前按"页 ID"把它改成 3/4 是误判 ——
  设备上被编辑器写回 2 后键盘依然可用，即证明 2 本来就是对的。**以后不要手改 `key`。**
- **★ 认知更正 2**：编辑器重存可能**重建系统键盘页**（该页默认上锁），把我们往键盘页加的代码覆盖掉
  （fix13 里 `printh 11` 消失即由此，不是用户删的）。本轮编辑器重存**没有**触发重建（`1.pa` 逐字节未变），
  但风险存在 → 见 §6 R2。

## 6. 已知限制 / 风险（都要知道）

| # | 风险 | 说明与对策 |
|---|---|---|
| R1 | 哨兵值 **500** 必须等于 `h` 在页面里的初值 | 若将来在编辑器里改了 `h` 的初值，**必须同步改 `5.pa` load 里的 `if(h.val!=500)`**，否则采收会误判 |
| R2 | 编辑器重存若**重建键盘页** → 丢掉 `printh 11` 与采收行 | 表现：屏上能显示新值，**但固件收不到**（屏固不一致）。**每次编辑器另存后跑一次 `_v6_verify.js`**，它会检查 `b210` 第 47/48 行 |
| R3 | 键盘页丢编辑时，"把阈值改成**恰好 500**"这一种编辑无法被采收 | `h.val==500` 会被当作"未编辑"。其余任何值都正常（这是选 500 作哨兵的代价） |
| R4 | 首次上电 `thr` = Program.s 初值 500 | 若开机那次推送因屏未启动而丢失，进设置页会先显示 500，**≤250 ms** 后由"页进入推送 + tm0"纠正为真值 |
