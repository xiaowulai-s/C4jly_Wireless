# v42 变更与验证记录：顶栏色条改用 `bco` 推送（修 P1-1 真因）

> 2026-09-30。基线：屏 `C4F7N_v8.HMI`（md5 `ad68fbd6`，**本次未改动**）+ 固件 v41（md5 `d7969411`）。
> 关联：`../评审与方案/屏端-固件端接口对照审计_2026-09-30.md` §六 P1-1 / §七 N3。

## 1. 背景：v40 的"修复"被真机否定

上午审计把 P1-1 判为"色条只推主页、其余 3 页永不更新"，v40 据此改成按页后缀推送：

```c
snprintf(n, sizeof(n), "dvr%s", sfx);  tjc_set_pco(n, stc);   /* [v40] */
```

但 2026-09-30 真机验证 **颜色不变** ⇒ 真根因不是"漏推其它页"，而是**属性用错**：

| 事实 | 说明 |
|---|---|
| `dvr` 的 `txt = " "` | **单个空格，无笔画** |
| `dvr` 的 `w=1024`、`h=2` | 靠**控件填充色**显示为一条 2px 细线 |
| `pco` 语义 | **文字前景色** —— 空格无笔画 ⇒ 推 `pco` **无任何可见效果** |
| `bco` 语义 | **控件背景色** —— 它才是铺满控件区域的填充色 |

⇒ 原实现（含 v40）4 页**都**改不动；屏上那条线实际是 `bco`=12777（≈深灰蓝）的**固定装饰线**。
（旁证：4 页初始 `pco` 各不相同 —— 主页/初始化 = 0、设置/历史 = 57149 —— 却从无人察觉异常，说明它从未生效。）

## 4. 待真机验证（1 项）

**让设备真报警**（打火机气体/标气触发浓度超阈值）→ 盯**顶栏那条 2px 细线**：

- 由固定深灰蓝 → **绿（正常）/ 橙（1 级）/ 红（2 级）**随之变化 = **修好**
- 仍不变 → 说明 `dvr` 的 `aph=127`（透明度）把 `bco` 也影响了 → 转**方案 B**（屏端换图片控件 + `tjc_pic` 换色图，与 `pc2d` 电量圆点同法，已证可行）

## 5. 注意

- ⚠️ 若实测**仍不变色**，不要再在固件侧换其它属性试 —— `dvr` 是"文本控件 + 空格"，能整块填充的只有 `bco`；再不行必须**换控件类型**（方案 B）。
- ★ 通用教训（已写入技能 `tjc-hmi-hmipack-edit`）：**`pco` 是文字前景色、不是填充色** —— 用「空格 + `pco`」做色条/色块**永远无效**。
- ★ 流程教训：v40 真机验证时用户只回报了"固件版本行"一项，当时却按"P1 五条全过"记档 ⇒ **验证清单必须逐项确认，不得由单项通过推定其余通过**。
