# v41 变更与验证记录：量产产品信息配置区

> 需求（用户 2026-09-30）：把**产品编号**与**固件版本**在程序中显式声明、可手动更改 —— 量产时为每台设备配置不同信息再烧录。
> 承接 v40（接口审计 P1 修复：信息行改为从固件取真值）。**屏端零改动**。

## 1. 设计：一个专门的量产配置区

新增 **`C4F7N_Demo/Core/Inc/product_info.h`**（集中、显眼、量产时只看这一个文件）：

```c
/* 固件版本 —— 整批相同; 屏端设置页"固件版本"行显示的就是它 */
#define PRODUCT_FW_VERSION   "V1.0-b41"

/* 产品编号 —— 量产时逐台修改; 屏端设置页"产品编号"行显示的就是它
 *   填字符串 : 以本值为准(是否覆写设备内旧值, 见下方写入策略)
 *   填 ""    : 不指定, 改用 MCU 唯一 ID 自动派生 "SN-C4F7N-XXXXXXXX" */
#define PRODUCT_SN           "C4F7N-26001"

/* SN 写入策略(只影响"设备内已有记录"的情况)
 *   1 = 宏值与设备内记录不一致时覆写 (推荐: 量产/研发改号后重烧即生效)
 *   0 = 仅当设备内无有效记录时才写入 (保护已出厂编号: 仅重烧固件不会改掉它) */
#define PRODUCT_SN_FORCE_WRITE   1
```

## 3. 量产流程（无需额外工具）

1. 打开 `product_info.h`，改 `PRODUCT_FW_VERSION`（整批）与 `PRODUCT_SN`（逐台）
2. 编译 → 烧录
3. 设备上电时自动把 SN 写入自身 Flash 末页，并把两项同步显示到屏端"设置页"
4. 逐台重复 1~3 即可（`PRODUCT_SN_FORCE_WRITE=1` 时，改号重烧会覆写设备内旧值）

> 若不想逐台维护编号：把 `PRODUCT_SN` 置为 `""`，固件会用 MCU 唯一 ID 自动派生 `SN-C4F7N-XXXXXXXX`（仍逐台唯一、且持久化）。

## 6. 注意

- ⚠️ **SN 落盘依赖 MCU 内部 Flash 末页（`0x0803F800`）**：换 MCU 会丢 SN（需重烧或在 `PRODUCT_SN` 里重填原编号）。
- ⚠️ `PRODUCT_FW_VERSION` 请与内部迭代号保持对齐（本次 v41 → `V1.0-b41`），每次编译前手动更新。
- ⚠️ **屏端 `fw`/`sn` 的 `txt_maxl` 必须 ≥ 推送文本字节数**：前缀 `固件版本: ` / `产品编号: ` 各占 **10 B**（4 汉字=8B + 冒号空格=2B）⇒ 可用余量 = `txt_maxl − 10`。用户已将其加宽到 **30**（`V1.0-b41` 用 8 B、`C4F7N-26001` 用 11 B，余量充足）。
- ⚠️ **烧录后务必手动复位或断电重上电**：本机带电池，不复位则 MCU 继续跑旧程序，会误判成"改动无效"。
