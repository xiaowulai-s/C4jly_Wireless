## 2. 固件改动

### 2.1 `param_t`：28 B → **40 B**，`PARAM_VERSION` 2 → 3

```c
uint32_t magic;      uint32_t version;
int32_t  cal_k;      int32_t  cal_b;
int32_t  cal_raw0;   /* 新增：零点标定的原始读数；0x7FFFFFFF=未标定 */
uint32_t cal_ts;     /* 新增：标定时刻 epoch(秒)；0=未标定 */
uint32_t hist_base;  /* 新增：历史有效数据的起始代数（逻辑清空） */
uint16_t thr_hi;     uint16_t thr_lo;
uint8_t  buzzer_en;  uint8_t  cal_valid;   uint16_t _rsv;
uint32_t crc;
```

- **删** `unit_mode`（决策 15）
- `cal_valid` 现在**真正被读取**（`cal_upload_status` 判"是否已标定"）

### 2.2 写入方式：整扇区擦写 → **扇区内追加式写**

单条 40 B，每扇区 **102 槽**；`param_save()` 写入下一个空白槽（`find_free_slot()`），写满才擦一次。

- 掉电最多丢**最后一条**，旧记录仍在 → 不再静默回默认值（解决 P1-2）
- 擦除频率降约 100 倍（顺带解决写入寿命）
- `param_init()` 从**最后一槽往前**找第一条 `magic + version + crc` 全有效记录
- `param_factory()` **保留 `hist_base` 现值**（决策 13：恢复出厂不撤销"清空历史"）

### 2.3 `history`：新增**逻辑清空**

- 新增 `g_hist_base`（上电由 `param_get_hist_base()` 读入）
- `history_init()`：`maxhead < g_hist_base` → 视为无数据、`g_written = 0`
- `history_log()`：扇区头写 `seq = idx/HIST_CAP + g_hist_base`（绝对代数）
- `history_clear()`：`g_hist_base = maxhead + 1` + 写参数区（1 次，约 50–80 ms）→ **不擦 2047 个扇区**（省下约 92 秒）
- `HIST_SECTOR_START` 仍为 `1`（未动历史区规划）

## 5. 你必然会感知到的**两个代价**

### ① `PARAM_VERSION` 2 → 3 ⇒ 首次上电回默认值

`param_init()` 判 `version != 3` → 无效 → 擦扇区填默认。所以**升级后标定系数与阈值（500/100）都会回默认，必须重新标定一次**。这是版本迁移的必然结果，已提前告知。

### ② 「重置峰值」能力消失 ⇒ 最大/最小值只在**泵启动**时清零

原历史页 `prst` 按钮（0x01）会调 `stats_reset()` 清 `g_peak/g_min`（主页 `cma`/`cmn` 显示的"最大值/最小值"）。现在 0x01 改为清空历史，`stats_reset()` 已删 → **手动清零峰值不再可用**。

现有唯一清零时机：`hmi_on_pump_toggle()` 中泵启动时（`if (pump_get()) { g_peak = 0.0f; g_min = 4294967.0f; }`）—— 语义上等于"新一轮测量开始"。

> 如果你希望保留手动清零，可在主页另加一个按钮（新增 1 个命令码）；告诉我即可。
