## 二、★ 关键发现：TX 引脚早已配好，只需开 TE

`UART4->CR1 = UE|RE|RXNEIE` 一直**只有接收使能，没有 TE** ⇒ UART4 只能收不能发。

但 `sensor_init()` 里 **PC10（USART4_TX）早已配成 `GPIO_MODE_AF_PP`**，
GPIO 配置完全正确 —— 所以改动只是 **CR1 加一个位**：

```c
UART4->CR1 = USART_CR1_UE | USART_CR1_TE | USART_CR1_RE | USART_CR1_RXNEIE;
```

这点很重要：说明硬件设计本来就预留了下行能力，只是固件没开。

## 三、改动（2 文件，均 GBK）

### 3.1 `BSP/Src/sensor.c`（5386 → 6779 B）

**① CR1 补 TE**

```c
  /* [v62] 补 TE: 原先只有 RE, UART4 只能收不能发; PC10(TX) 在上方已配成 AF_PP,
   *   这里只需开发送使能即可下发厂商标定/配置指令。 */
  UART4->CR1 = USART_CR1_UE | USART_CR1_TE | USART_CR1_RE | USART_CR1_RXNEIE;
```

**② 三个指令数组定义**（放在 `sensor.c` 而非头文件，原因见第五节）

```c
const uint8_t SENSOR_CMD_ZERO_HW[SENSOR_CMD_ZERO_HW_LEN] = {
  0x23, 0x57, 0x31, 0x36, 0x36, 0x21
};
const uint8_t SENSOR_CMD_LO15_A[SENSOR_CMD_LO15_LEN] = {
  0x23, 0x57, 0x38, 0x31, 0x35, 0x30, 0x30, 0x32, 0x35, 0x39, 0x21
};
const uint8_t SENSOR_CMD_LO15_B[SENSOR_CMD_LO15_LEN] = {
  0x23, 0x57, 0x38, 0x36, 0x30, 0x30, 0x31, 0x35, 0x35, 0x44, 0x21
};
```

**③ 发送函数**

```c
void sensor_send_cmd(const uint8_t *buf, uint8_t len)
{
  uint8_t i;
  if (buf == 0 || len == 0u) return;
  for (i = 0u; i < len; i++) {
    while ((UART4->SR & USART_SR_TXE) == 0u) { }
    UART4->DR = buf[i];
  }
  while ((UART4->SR & USART_SR_TC) == 0u) { }   /* 等最后一位真正移出 */
}
```

- 轮 `TXE`（发送寄存器空）→ 写 `DR` → 最后轮 `TC`（Transmission Complete）
- 9600 8N1 下 11 字节约 **11.5 ms 阻塞**
- **发送中不改 CR1**，避免影响 RXNE 接收中断
- 用法：`sensor_send_cmd(SENSOR_CMD_LO15_A, sizeof(SENSOR_CMD_LO15_A));`

## 六、★ 行尾陷阱（又一次命中）

逐文件探测结果：

| 文件 | 行尾 |
|---|---|
| `sensor.c` | **纯 CRLF**（LF=156 CR=156）|
| `sensor.h` | **混合**：offset 1157 处是**裸 LF**，且**末尾无换行符**（LF=71 CR=70）|

⇒ 补丁必须用「**按锚点原样替换**」，绝不整体重排行尾。
⇒ 断言写法：
- LF/CR 总数**只可增不可减**（本次在新增代码）
- **裸 LF 位置集合必须完全不变**
- 末尾换行状态不变
- 新增换行必须成对

## 十一、编译排错记录（12:48~13:10）

首次 Rebuild 失败：`sensor.c(142): source file is not valid UTF-8`，19 errors。

### 根因：我的注释笔误 —— `*/` 提前闭合

```
139: /* ---- [v62] 厂商下行指令... ----              ← /* 开头
140:  * 零点校准 ...
141:  * 15ppm 下限 ... 之后传感器侧 0~15ppm 截零 */   ← ★ 这里就闭合了
142:  * 本文件被 main.c / ... 定义一份。 */          ← 落到注释外，被当代码解析
```

第 142 行被当代码 ⇒ `type specifier missing` / `expected ';'`；
同时该行 GBK 字节被 AC6 按 UTF-8 解析 ⇒ `invalid-source-encoding` / `unexpected character <U+036C>`。

★ **三个报错是同一根因的两种表现**，我一开始误判为「AC6 不支持 GBK 注释」。

### 处置：改为纯 ASCII 注释

```c
/* ---- [v62] vendor downlink commands (bytes confirmed by user 2026-10-12) ----
 * ZERO_HW  23 57 31 36 36 21          : send ONLY when no test gas present
 * LO15_A/B 11 bytes each, send A then B : sensor then clamps 0..15ppm to 0
 * Arrays are defined here (not in sensor.h) because sensor.h is included by 4 TUs. */
```

★ 顺带规避整个编码纠缠。**后续给 GBK 文件写注释一律用 ASCII。**
