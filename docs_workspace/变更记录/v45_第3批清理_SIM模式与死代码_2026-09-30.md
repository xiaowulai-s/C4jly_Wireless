### 2.4 `protocol.h`（UTF-8）

```c
#define OBJ_TEST_BTN    "ptg"    /* 主页"开始测试/停止测试"按钮 (printh 0x24);
                                  * ⚠️ 屏端 txt_maxl = 8 字节, 恰好容纳 4 个汉字("开始测试"); 改文案须同步改屏端 maxl */
```

### 2.5 `product_info.h` + `device_id.c`（UTF-8）—— N5

问题：三方长度不匹配，且越界是**静默**的。

| 环节 | 上限 |
|---|---|
| 固件 `DEVICE_ID_SN_MAX=24` ⇒ `strncpy(…, 23)` | 23 字符 |
| 屏端 `sn`：`txt_maxl=30` − 前缀 `产品编号: `（10 B） | **20 字符** |
| `PRODUCT_SN` 校验 | **无** |

修法：
```c
/* product_info.h */
#define PRODUCT_SN_DISPLAY_MAX   20u   /* = 屏端 txt_maxl(30B) − 前缀 "产品编号: "(10B) */

/* device_id.c */
typedef char product_sn_len_ok[(sizeof(PRODUCT_SN) - 1u) <= PRODUCT_SN_DISPLAY_MAX ? 1 : -1];
```
⇒ 超长**直接编译报错**（不再是屏上悄悄少几位）。断言通过时 `typedef` 不生成代码 ⇒ **产物无影响**。

## 3. P2-6 为何跳过（重要）

审计原判：设置页 `load` 的 `if(h.val!=500){thr=h.val}` 恒为假（依据"进页时 `h.val` 恒被重绘为初值 500"）。

**本次复核发现该依据可能不成立**：实测属性 **`h` 是 type54 且 `vscope=1`（全局作用域）** —— TJC 全局控件**切页时值会保留**，`h.val` 并不必然回到 500 ⇒ 该 `if` **可能真会执行**（属"屏端 h 已改但固件尚未收到"的容错）。

**实测方法**：把阈值改到非 500 → 退出设置页 → 再进，看 `h` 是否仍显示该值。
- 保留 ⇒ 有效容错逻辑，保留不动
- 回 500 ⇒ 确为冗余，再删
