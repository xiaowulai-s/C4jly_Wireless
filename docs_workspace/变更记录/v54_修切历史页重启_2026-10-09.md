## 一、真机现象与定位

**现象**：点击「开始测试」并切换到历史页 ⇒ 设备重启（**只重启一次**，不是周期性）。

### 关键推理：为什么「只重启一次」证明根因

IWDG 一旦启动**不可关闭**。若真是 IWDG 反复触发，重启后仍会卡在同一处⇒ **无限重启循环**。
而观察到的现象是「**只重启一次**」⇒ 复位后 `g_test`（`static` 变量，随复位清零）不再置位 ⇒ 不再进历史页循环 ⇒ 一次即停。

⇒ **结论：不是 IWDG 反复触发，而是「单轮 `app_refresh()` 阻塞时间 > IWDG 窗口（最快 LSI 2133 ms）」。**

### 真因（v53 窗口核算的疏漏）

v53 我按「正常发送」核算窗口，**漏了 `HAL_UART_Transmit` 的超时是会叠加的**。

**触发链**（`main.c` 历史页刷新段）：

```c
else if (g_page_now == 2u && (tot != s_total || ...)) { ... refill_table(); }
else if (g_page_now == 2u && (hn - rlast >= 5000u))  { ... refill_table(); }
```

`tot = history_total() = g_written`，**测试中每秒 `history_log()` 使 `g_written` 递增** ⇒ `tot != s_total` 每秒成立
⇒ **`refill_table` 在「测试中 + 历史页」每秒执行一次**（注释里写的「5s 兜底」只在非测试期成立）。

**而 `refill_table` 单次调用**：
- **24 次 flash 读**（`history_read_page` 逐条 `w25q16_read`）
- **78 次串口发送**（24 行 × 3 列 + 5 条统计 + 1 条页码）

| 场景 | `refill_table` 单次耗时 |
|---|---|
| **正常**（@115200，37B 帧 ≈ 3.2 ms）| ≈ **169 ms** |
| **屏端/线路异常时**（每次 `HAL_UART_Transmit` 都等满 100 ms 超时）| **78 × 100 = 7800 ms** ☠ |

7800 ms ≫ 2133 ms ⇒ **硬件狗复位**。这是**我 v53 核算时漏掉的放大路径**，不是窗口本身算错。

## 二、三处修复（层层加固，不只靠调窗口）

### 修 1 · 测试中 `refill_table` 降频到 5 s

```c
else if (g_page_now == 2u && !g_test && (tot != s_total || ...)) { ... }
```
加 `!g_test` 限制：**测试中只靠 5 s 兜底刷新**（历史表 5 s 更新一次，用户可接受）；非测试期保持「条数变化即刷新」的实时性。

⇒ 消除「每秒全表重绘」这个放大源。

### 修 2 · `refill_table` 行循环内每 6 行喂狗

```c
for (i = 0; i < HIST_TBL_ROWS; i++) {
  if ((i % 6u) == 0u) iwdg_feed();     /* 24 行 => 喂 4 次 */
```
`refill_table` 是全工程最长的单次阻塞操作。**循环内喂狗保证「单次调用」也不会超窗口**，即使前面任何一条修复被回退也能兜住。

### 修 3 · `HAL_UART_Transmit` 超时 100 ms → 20 ms（`tjc_cmd.c`）

| | 原值 | 新值 |
|---|---|---|
| 单次超时 | 100 ms | **20 ms** |
| `refill_table` 最坏叠加 | 78 × 100 = **7800 ms** | 78 × 20 = **1560 ms**（落在窗口内）|
| 正常发送耗时 | 5.3 ms（最长 61 B 帧）| 5.3 ms → **不受影响**（20 ms 有 3.8 倍余量）|

> 这一条是**根因级**的修法：超时从「100 ms 的容错」改成「20 ms 的容错」，任何单点卡顿都不再被放大成秒级。

## 三、修复后的时间账（重算）

| 场景 | 单轮最坏 | IWDG 窗口（最快 LSI 2133 ms）|
|---|---|---|
| 测试中 + 历史页（修后）| 每 5 s 一次；单次 ≈ 169 ms（正常）/ 1.6 s（异常）| **1.6 s < 2.13 s** ✔ |
| `history_log` 扇区擦除 | ≤ 500 ms（仅新扇区首点）| ✔ |
| `refill_table` 单次（任何触发路径）| 循环内每 6 行喂狗 ⇒ **不可能累计到超窗口** | ✔ |

⇒ 三道防线：① 降频（消除每秒触发）② 循环内喂狗（单次调用也不超）③ 超时缩短（异常不放大）。
