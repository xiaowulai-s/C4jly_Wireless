## 一、P0-A · 电池自检判据恒为真 → POST 永远显示「自检通过」

### 根因

```c
selftest.c:16   r->batt_ok = (battery_get_pct() >= 0);
battery.c:130   int battery_get_pct(void) { return g_batt_pct; }
```

`battery_get_pct()` 返回 `int`（取值恒为 `0~100`）⇒ `>= 0` **恒为真** ⇒ `batt_ok` 永远是 1。

而 `battery.c:157` 的 `if (v < 5.0f) return;` 把无效读数（未接电池 / 电池故障导致电压异常低）**直接丢弃、不留痕迹**，自检层拿不到任何信息。

★ **这正是 10-08 那次电池故障（电池端子 0.003V、PCM 切断）未被固件自检发现的原因** —— 当时是靠外部万用表定位的。
★ `selftest.h:15` 的注释本就写着「电池采样有效(非<5V 无效读数)」，**实现与注释不符**。

### 修法（3处，+11 行）

| 文件 | 改动 |
|---|---|
| `battery.c` | 新增 `static uint8_t g_batt_valid`；`<5.0f` 早退分支改为 `{ g_batt_valid = 0; return; }`；有效路径置 `g_batt_valid = 1`；新增 `uint8_t battery_valid(void)` |
| `battery.h` | 声明 `uint8_t battery_valid(void);`（附注释：**不可用 `battery_get_pct()>=0`，恒真**） |
| `selftest.c` | `r->batt_ok = battery_valid();` + 5 行注释说明原判据为何恒真 |

### 时序已验证

`main.c` 内顺序为 `battery_init()`(offset 786) → `battery_poll()`(804) → `selftest_run`(1184)
⇒ `g_batt_valid` 在自检执行前**已被真实采样填充**（`battery_init()` 内含一次 `battery_poll()`），不是读到初值 0 的假阴性。

## 二、P0-B · 零点标定在真正洁净空气（raw=0）下报「非法值」失败

### 根因

```c
main.c:1022      if (raw <= 0.0f) { cal_report(CAL_REQ_ZERO, CAL_E_BADRAW); return; }
sensor.c:120float sensor_read_raw(void) { return g_ppm_now; }   /* ← 无 0 保护 */
```

`sensor_read_ppm()` 有 `if (g_ppm_now == 0.0f) return 0.0f;`（预热保护），
**但 `sensor_read_raw()` 直接返回原始值、没有这层保护**。而**洁净空气中原始读数本就是 0**
⇒ 在真洁净环境做零点标定会误报「标定失败：原始读数为 0，检查探头」。

★ **该判据与 v49 刚引导用户做的事直接冲突** —— v49 就是要用户在洁净环境标定。
★ 该判据本意是防「探头没出数」，但 `cal_precheck()`（`main.c:906`）**已经检查了 `sensor_online()`**，属**冗余且有害**。

### 修法（1 行 + 注释）

```c
if (raw < 0.0f) { cal_report(CAL_REQ_ZERO, CAL_E_BADRAW); return; }   /* <= 改 < */
```

`<= 0` → `< 0`：负值仍防护（不可能发生，纯防御），**0 不再被误判**。
量程处（`main.c:1053`）的 `raw1 <= 0.0f` **保持不变**（`raw1` 为 1000ppm 标气读数，恒 > 0），仅补注释防止后人误改。

## 六、追加（2026-10-09 真机反馈后）：「电池检测异常」→「电池采样异常」

### 起因：用户实测**拔电池 + 接充电器，上电仍显示「自检通过」**

**结论：这是符合逻辑的正确行为，不是修复失效。** 根因在硬件拓扑：

```
充电器 16.8V → CHG_IN → D2(SS34, 单向) → BATTERY → CN1 → BAT_SW ← 电量采样点在这
```

电量采样点是 **`BAT_SW`（电池开关之后）**，不是电池座。电池不在位但插着充电器时，
充电器经 SS34 **单向灌入** `BATTERY` 节点 ⇒ `BAT_SW` 被充到 ≈16.35V ⇒ ADC 读数有效（≫5V）
⇒ `g_batt_valid = 1` ⇒ `batt_ok = 1` ⇒ 显示「自检通过」。

⇒ **只要充电器接着，MCU 原理上就区分不出「电池在位」与「电池不在位但外部供电正常」。**

### ★ 我在排查报告里的场景 2 写错了

原报告写「拔电池上电 → 应显示红『电池检测异常』」，**在这个硬件拓扑下这个检验做不出来**：
不接充电器时 `BAT_SW` 无电 ⇒ **屏幕根本点不亮** ⇒ 谈不上自检。这是我的判断失误 ——
只考虑了「读数有效性」，没考虑 `BAT_SW` 在接充电器时必然被充高。

### 改法（用户裁定「接受现状」，走方案 A）

| 项 | 改动 |
|---|---|
| 文案 | `电池检测异常` → **`电池采样异常`**（12 B，`pst_i` 的 `txt_maxl=50` 空间充裕） |
| 函数头注释 | `hmi_update_selftest()` 补 5 行，**明确 `batt_ok` 的语义是「采样链路是否有效」而非「电池是否在位」**，并写清硬件原因与「要真正检测在位需硬件」 |

**屏端零改动**（`pst_i` 文字控件属性无需变动）。
