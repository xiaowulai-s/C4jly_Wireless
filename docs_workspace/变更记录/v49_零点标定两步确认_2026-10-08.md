## 1. 动机

用户提出：零点标定在**户外**进行时，环境本底约 **10 ppm**。原逻辑只判`ppm < CAL_ZERO_MAX_PPM(50)`，
户外 10 ppm 完全通过 → 被写成零点 → **真实 10~25 ppm 的泄漏会显示 0**，形成安全盲区。

已确认的风险与决策（用户 2026-10-08 拍板）：

| 项 | 决策 |
|---|---|
| 标定环境 | 户外（不可改） |
| 标定前是否显示当前浓度 | **要**（让操作者自己判断是否洁净） |
| 是否下调 `CAL_ZERO_MAX_PPM` | **暂不**（保持 50 ppm，见 `docs/评审与方案/`） |
| 防护方式 | **两步确认法**（本版） |

## 2. 交互设计

| 步骤 | 用户动作 | 按钮 `c0` | 右栏 `crs_s1` | 是否写 Flash |
|---|---|---|---|---|
| ① 第一次点击 | 点「零点标定」 | `待确认` | `当前 10ppm，须洁净空气，3秒内再按确认` | ❌ |
| ② 窗口内再点，浓度未变 | 3 s内 再点一次 | `执行` | `零点标定完成 补偿-12ppm，请确认环境洁净` | ✅ |
| ③ 窗口内再点，浓度变了 | 3 s内 再点一次 | `已作废` | `浓度已变化，请重新点击零点标定` | ❌ |
| ④ 超窗后再点 | 间隔 > 3 s | `待确认` | 同①（视为新的第一次，重新开始） | ❌ |

**浓度变化判据**：窗口内两次读数差> `CAL_ZERO_STABLE_PPM = 3.0f` ppm → 判环境已变，本次作废。
（ppm 本身有±1 量级抖动，3.0 是"同一环境的自然波动"与"环境真的变了"的分界。）

**换操作即作废**：进入量程标定（`cal_do_span`）或恢复出厂（`cal_do_factory`）时清`g_cal0_armed`，
避免在别的操作后残留的确认窗口被误用。前置校验失败（未接通/预热中/浓度高）同样清零。

### 成功文案为什么少了「原始码」

`crs_s1` 的 `txt_maxl = 40`（字节，GBK 中文占 2 字节）。加入洁净提醒后必须腾空间：

```
零点标定完成 补偿-999ppm，请确认环境洁净   = 40 B  ← 刚好卡满
零点标定完成 补偿-12ppm（原始码 1234）    = 39 B  ← 原v34 文案
```

两者无法共存（v34 的「原始码」是调试信息，非用户必需），故**保留补偿值 + 洁净提醒，移出原始码**。
补偿值本身已能反映零点偏移量，诊断用途可通过 map/串口观察。

## 4. 编码与改法注意

- `main.c` 为 **GBK / LF**，改动全部在 Python 里以 `str` 替换后 `encode('gbk')` 写回，
  脚本内含 **唯一锚点校验（8 处全部 count==1 才落盘）+往返断言 + `U+FFFD` 检查**。
- ★ 历史事故：`readFileSync(P,'utf8')` 读 GBK 再写回 → 全文件中文变 `U+FFFD`。本次未触碰。
