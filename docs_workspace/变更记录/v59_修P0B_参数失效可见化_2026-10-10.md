## 二、★ 方案方向的重大修正（我上一版说错了）

### 2.1 我上一版的方案

我原写：「用**独立备份扇区**保住参数 —— 写满时①备份 ②擦主扇区 ③从备份恢复」。

### 2.2 用户前提让这个方案变成了过度设计

用户明确：**历史数据与参数区都可丢弃，恢复出厂后重设全新参数**。

⇒ **"保住参数"这个目标本身消失了。** 我设计的备份区、保留槽、双副本，
**全部是为了保住数据** —— 在"可以重设"的前提下，它们是**不必要的复杂度**。

### 2.3 修正后的目标：不是「保住」，而是「让丢失可见」

擦除窗口掉电的真正危害**不是「参数没了」**（用户说了可重设），
而是 **「用户不知道参数没了」**：

| 现象 | 用户认知 | 实际后果 |
|---|---|---|
| 阈值悄悄回到 500/100 | 「我设的是 800」 | **报警门限失效，可能漏报** |
| 标定系数回到 1000/0 | 「我标定过」 | **浓度读数失准，检漏结果不可信** |

⇒ 静默才是危害所在。方案改为：**保证丢失一定被看见**。

## 三、实现

### 3.1 标志存放（`param_store.h` / `param_store.c`）

标志必须**跨擦除窗口存活**，因此**不能放在扇区 0**（会被一起擦掉）。

| 项 | 值 | 说明 |
|---|---|---|
| 地址 | `PARAM_FLAG_ADDR = 0xFFE000u` | W25Q64 **扇区 2047** 起始 |
| 结构 | `[0..3] magic = 0x464C4732`（`FLG2`）· `[4..7] 标记 = 0x5A5A5A5A` | 两个 `uint32_t` |
| 判读 | `magic && 标记` **同时匹配** | 避免扇区初始全 `0xFF` 被误判为「已置标志」|

**占用扇区 2047 的代价**：历史区从 2047 个扇区减为 **2046 个**，
容量 139.6 万 → 139.5 万条（**-682 条 ≈ 16.8 分钟的量**）。
★ 该代价在本项目的使用前提下（测试机、历史数据可弃）为**零成本**。

### 3.2 生命周期

| 时机 | 动作 |
|---|---|
| `param_init()` 走 `dump_defaults()` 分支（**主扇区全失配**）| **置位**标志 |
| 上电后 `hmi_update_selftest()` 读标志 | POST 页显示「**参数已重置，请重新设置阈值**」，**橙色** |
| 用户重设参数 → `param_save()` 成功落盘 | **清零**标志（用户语义：重新设过就算处理过了）|

### 3.3 显示端（`main.c` 的 `hmi_update_selftest()`）

```c
if (fail == 0 && rst)  snprintf(cb, sizeof(cb), "<参数已重置，请重新设置阈值>");
else if (fail == 0)    ...「自检通过」
...
tjc_set_pco(OBJ_SELFTEST_I, fail ? C_STRIP_RED
                          : (rst ? C_STRIP_ORANGE : C_STRIP_GREEN));
```

- **优先级**：故障文案 > 参数已重置 > 自检通过（自检故障时不显示重置提示，避免混淆）
- **颜色语义**：红=故障 / **橙=警告但非故障** / 绿=全过（`C_STRIP_ORANGE = 62689` 已在用）
- 判据加了 `rst` 变化检测（`s_rst`），避免每 250ms 重发

### 3.4 文案字节核验

| 项 | 值 |
|---|---|
| 文案 | 参数已重置，请重新设置阈值 |
| GBK 字节 | **26 B**（`pst_i` 的 `txt_maxl=50`，充裕）|
| 字节来源 | `w.encode('gbk')` **现算**（铁律：禁止手写 `\xNN`）|

## 四、验证证据

| 项 | 证据 |
|---|---|
| 编译 | **0 Error / 0 Warning**，`Program Size: Code=41744 RO-data=1864 RW-data=100 ZI-data=2724` |
| Code 变化 | 41444 → **41744（+300）** |
| hex 校验 | 2735 行整行累加（含 CC），**0 错** |
| hex md5 | **`d052f57858a3cc9c1f7d46aaf571d17b`** |
| 标志函数 | `param_flag_read` 4 处 · `param_flag_set` 3 处 · `param_reset_flag` 1 处（声明）|
| 置位/清位 | `param_flag_set(1u)` 1 处（`param_init`）· `if (param_flag_read()) param_flag_set(0u)` 1 处（`param_save`）|
| 扇区数 | `history.h` 的 `HIST_SECTORS 2046u` 1 处 |
| 显示端 | `param_reset_flag()` 2 处 · `s_rst` 声明 1 处 · 橙色分支 1 处 |
| **axf 字节级** | 新文案「参数已重置，请重新设置阈值」**命中 1**；旧文案「自检通过」**仍在 1**（未被误删）|
| 编码/行尾 | `main.c` GBK/LF=1341 · `param_store.c` GBK/**CRLF=144** · `param_store.h` GBK/LF · `history.h` UTF-8/LF —— **全部与改前一致**，`EF BF BD` 全 0 |

⚠️ **一个踩坑**：`param_store.c` 是 **CRLF 行尾**（记忆中此前记的是 LF），首次补丁脚本用 LF 锚点 → `count=0`。
处置：脚本内加 `LF2CR = lambda s: s.replace('\n','\r\n')` 统一转换，并加两条断言
（`out.count(b'\n') == out.count(b'\r\n')` 确保无裸 LF；CRLF 增量 == 替换文本净增行数）。

## 五、真机验证清单

| # | 场景 | 期望 |
|---|---|---|
| 1 | 正常上电（参数区完好） | 绿「自检通过」，**不显示**重置提示 |
| 2 | 改一次阈值 → 重启 | 绿「自检通过」，标志应已被 `param_save` 清零 |
| 3 | **恢复出厂 → 重启** | 参数已回到默认 ⇒ 此时读 `param_save` 路径会清标志 ⇒ 应显绿「自检通过」 |
| **4** | **人为损坏参数区**（如用编程器把扇区 0 全擦成 `0xFF`）→ 上电 | **橙「参数已重置，请重新设置阈值」** ← P0-B 决定性检验 |
| **5** | 承4 之后**改一次阈值** → 重启 | 提示**消失**，恢复绿「自检通过」（标志被清）|
| 6 | 历史页 | 记录数上限 -682 条（其余表现正常）|

**第 4 项是核心检验**，可用编程器或 `erase-pas` 类工具预置扇区 0 全 `0xFF` 来模拟"擦除窗口掉电"的最终状态。
第 5 项验证标志的清除路径 —— 这条不做的话，提示会一直挂着变成"狼来了"。

## 六、本版未做

| # | 级别 | 问题 | 说明 |

| C | ~~P1~~ | `hist_base` 与易失参数同扇区 | **降级不做** —— 在"参数区可弃"的前提下，参数区失效导致 `hist_base` 归 0 的后果只是「历史页数字不对」，而历史数据本身已声明可弃 ⇒ 不构成数据风险 |

在本项目的前提下（测试机、历史数据可弃）该前提不成立 ⇒ 危害降为"显示难看"，不值得动参数区布局。
