### ★ 关键发现：只放要改的页，其余页逐字节不动

hmipack 会把工作目录里**存在**的 `.pa` 重写，**不在目录里的页从模板原样复制**。

后者正是 `lib/page.js` 警告过的"非常量字段"。

**规避**：本轮 `6.pa` 无需改动 → **不进工作目录** → 完全不受影响。
被重写的 4 页（0/2/4/5）头部 +40 本就是 `0x02000000`，归一化是 no-op，唯一副作用 = **stamp 重算**。

### 3.3 键盘回读链路设计（2-7/2-8/2-9）

```
屏端 点 h → 弹出 keybdB → 输入 → 按 OK(b210)
   b210 脚本: 写回 h.val/.txt → printh 11 → page 回设置页
        ↓ (0x11 单字节)
固件 HAL_UART_RxCpltCallback → hmi_on_thr_hi_set()   ← ISR 只置 g_thr_hi_req
        ↓
主循环 app_refresh → thr_hi_readback_poll()
   → tjc_get("h","val")   500ms 超时, 最多重试 5 次
        ↓
应答帧 → hmi_get_response() → thr_apply_hi_val(v)
   → 钳位 (THR_HI_MIN..MAX 且 ≥ thr_lo) → PP.thr_hi → thr_commit()
   → g_thr_dirty → 主循环 app_apply_threshold() 下发 h
```

**关键点**：`tjc_get` **不在 ISR 里发**（沿用既有 RTC 校时的同一套做法），避免中断内阻塞发串口。

### ★ 编译踩坑及更正（重要，已写进 `AGENTS.md` §2）

之前判断"**必须关 Keil GUI**（具名互斥体独占）"—— **这个归因是错的**。今天 Keil 进程已确认全部退出（`tasklist` 无匹配），**仍然 `EACCES`**。

真因是 **spawn 方式**：

| 调用方式 | 结果 |
|---|---|
| `execFileSync(UV4, args)` / `spawnSync(UV4, args)` 直接 CreateProcess | ❌ **`EACCES`，52 ms 立即失败，无日志产出** |
| `spawnSync('"...UV4.exe" -j0 -r "..." -o "..."', {shell:true})` 经 cmd | ✅ **exit 0，正常编译** |

**权限边界实测**：工作区内的 exe（`tools/extract-pas.exe`）直接 spawn ✅；系统 exe（`tasklist.exe`）✅；**`D:\KEIL` 下的 exe 直接 spawn ❌**。→ 跨目录直接 CreateProcess 被拦，走 shell 可绕开。

**验证编译是否真的发生**：只看日志里有没有逐文件 `compiling xxx.c...`。首次用 `-b` 时日志只有 `Build Time Elapsed: 00:00:00` —— 那是"已是最新、**未编译**"，不能当证据（你此前 10:03 已在 GUI 里编过一次）。必须用 `-r` 或清产物后 `-b`。

## 6. ★ fix11b 追加修复（2026-09-22 10:22）—— 初始化页进不去的真因

**触发**：用户烧录 fix11 + v19 后反馈「开机不进初始化页，一直主页」，并实测确认：**初始化页完全没出现**（非闪现）、**编辑器页面列表里初始化页 ID = 4**。

### 6.1 真因（两条，缺一不可）

**① 页号语义搞错了（主因）**

TJC 的页面 ID = **编辑器页面列表的顺序**（= `main.HMI` 里 pa 资源的排列 `4,0,5,2,6`），**不是 `.pa` 文件名里的数字**（那只是资源槽号，删页后不重排，所以是 `0,2,4,5,6` 这种不连续值）。

| 页面 ID | `.pa` 文件 | 页名 |
|---|---|---|
| 0 | `4.pa` | 主页 |
| 1 | `0.pa` | 历史曲线 |
| 2 | `5.pa` | 设置 |
| 3 | `2.pa` | keybdB |
| **4** | `6.pa` | **初始化** |

→ `Program.s` 的 `page 6` 与固件的 `tjc_page(6)` **都指向不存在的页** → 上电永远进不了初始化页。**这是长期存在的 bug，不是本次回归**（`tjc_page(6)` 在 09-18 的备份里就存在）。

→ **旁证**：`h.key` 原为 **2**，而 keybdB 的 ID 是 **3** → 点 `h` 弹出的是**设置页自己**，所以键盘输入链路从来没生效过（即便修好 `0x11` 回读也没用）。

**② 我自己造成的缺陷**：`Program.s` 为保持块尺寸 878B，把 302 个补白空格追加到了**最后一行**，而那行正是 `page 6`

| 版本 | 第 8 行 | 字节 | **字符** |
|---|---|---|---|
| fix10 | `page 6 … //上电刷下到0页` | 52 | **42** |
| fix11 | `page 6 …` + 302 空格 | 379 | **358** ← 超限 |

fix10 全文最长行仅 **169 字符** → fix11 那行 358 字符**超过 TJC 单行字符上限，该行语句失效**。

> 两条都要修才恢复：页号错 + 超长行失效，是**双重拦截**。

### 6.4 两个新踩坑（已写进 `AGENTS.md`）

1. **`page.set()` 给数值属性必须传 number**：传字符串 `'3'` 会被 `encode()` 当成 ASCII → 写成 `0x33`（51）而非 `0x03`。
2. **`.HMI` 被 USART HMI Editor 打开时会 EBUSY 锁住** → 读/构建要用副本，产物写新文件名，不要覆盖在用文件。
