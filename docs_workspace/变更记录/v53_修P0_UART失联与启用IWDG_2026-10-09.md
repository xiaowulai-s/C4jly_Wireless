## 一、P0-A · USART3 缺 `HAL_UART_ErrorCallback` → 屏幕永久失联

### 根因回顾

单字节 `HAL_UART_Receive_IT` 接收屏命令，只要屏端 UART 收到一个噪声字节（电磁干扰 / 屏重启脏数据 / 热插拔），
第二个字节在处理第一个的窗口内到达 ⇒ **ORE**。STM32 HAL 把 ORE 归为 blocking error：
调 `UART_EndRxTransfer()` 清掉 `CR1.RXNEIE`、`RxState` 置 READY。
**而错误分支只调 `HAL_UART_ErrorCallback`（本工程从未实现）⇒ `RxCpltCallback` 永不触发 ⇒ 永不重挂 ⇒ 屏幕接收永久失效且无法自愈。**

已核实（grep 全工程）：`HAL_UART_ErrorCallback` 零实现；`HAL_UART_Receive_IT` 仅 2 处调用，均在正常路径。

### 修法（`main.c`，约 20 行含注释）

```c
void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart) {
  if (huart == NULL || huart->Instance != USART3) return;   /* 只处理屏幕串口 */
  __HAL_UART_CLEAR_OREFLAG(huart);      /* 清 ORE: 必须先读 SR 后读 DR, 由宏完成 */
  hmi_get_reset();                      /* 丢掉可能残留的半帧, 避免下次被当业务命令 */
  if (HAL_UART_Receive_IT(huart, &rx_byte, 1) != HAL_OK) {
    g_rx_reattach_fail = 1;             /* 重挂失败记标志, 不再静默 */
  }
}
```

同时把 `RxCpltCallback` 末尾的 `HAL_UART_Receive_IT(...)` 改为 `(void)`显式忽略返回值（原为裸调用），
并新增 `static volatile uint8_t g_rx_reattach_fail;` 供观察。

★ **`hmi_get_reset()` 是必要的配套**：ORE 可能发生在 get 帧中途，残留半帧会让下一次 `hmi_get_feed()`
把帧内字节当业务命令执行（历史事故：秒值 `7` → `printh 07` 跳过初始化页）。

## 二、P0-B · 启用硬件独立看门狗（IWDG）

### 为什么必须启用

原「看门狗」是**软件模拟**（仅主循环喂狗）。HardFault / `Error_Handler` 一死循环 ⇒ 主循环停 ⇒
`NVIC_SystemReset()` 永不触发 ⇒ **设备永久死机，屏无任何提示**。
已核实硬件 IWDG 此前确认未启用（`stm32f1xx_hal_conf.h:52` 注释属实、`.uvprojx` 无该驱动文件）。

### 改动（3 处，跨固件 + 工程文件）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `MDK-ARM/C4F7N_Demo.uvprojx` | **加入 `stm32f1xx_hal_iwdg.c`** 到 HAL Driver 组（驱动文件本已存在于 `Drivers/`，只是未加入编译） |
| 2 | `Core/Inc/stm32f1xx_hal_conf.h` | `/*#define HAL_IWDG_MODULE_ENABLED*/` → `#define HAL_IWDG_MODULE_ENABLED` |
| 3 | `Core/Src/main.c` | include + 句柄/参数 + `iwdg_hw_start()` + 在 `iwdg_feed()` 里加 `HAL_IWDG_Refresh()` + 上电调用 `iwdg_hw_start()` |

### 参数与窗口核算

```c
#define IWDG_PRESCALER   32u   /* LSI/32 */
#define IWDG_RELOAD      4000u /* ≈3.2 s @40kHz */
```

| LSI 频率 | 实际窗口 |
|---|---|
| 30 kHz（最慢） | **4.27 s** |
| 40 kHz（典型） | **3.20 s** |
| 60 kHz（最快） | **2.13 s** |

**主循环最坏阻塞**（用于验算是否会误触发）：

| 操作 | 时长 |
|---|---|
| `w25q16` 扇区擦除（`wait_busy` 超时上限，`w25q16.c:30`） | ≤ **500 ms** |
| `refill_table` 阻塞发 1749 B @115200 | ≈ 152 ms |
| `cal_do_factory` 的 `HAL_Delay(200)` | 200 ms |
| **单轮最坏合计** | **≈ 0.7 s** |

⇒ **最快 LSI 情形（2.13 s）对最坏阻塞（0.7 s）余量约 3 倍**，不会误触发。

★ **IWDG 启动后不可关闭**（寄存器写保护，只能等复位），所以窗口算错的后果是**反复重启**。
故上电时把 `iwdg_hw_start()` 放在**所有 `HAL_Delay`（串口冷启动 1500+1000 ms）之后**，
且**先启动硬件狗、再 `iwdg_enable()` 开软件狗**，保证启动阶段就有硬件保护。

### LSI 时钟使能

```c
RCC_OscInitTypeDef osc = {0};
osc.OscillatorType = RCC_OSCILLATORTYPE_LSI;
osc.LSIState       = RCC_LSI_ON;
osc.PLL.PLLState   = RCC_PLL_NONE;   /* 必需: 关 PLL 省电, 避免 LSI 启用时被等待 */
(void)HAL_RCC_OscConfig(&osc);
```

## 四、⏳ 真机验证（★ IWDG 部分为重点，有反复重启风险）

### A. IWDG 是否会误触发（**先做这个**）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 上电后静置 **≥ 10 分钟**，不碰任何按键 | **不重启**（屏幕持续正常） |
| 2 | 进设置页改阈值（触发 flash 写） | **不重启** |
| 3 | 开始测试并等历史记录落盘（每 1 s 一次 flash 写，持续 10 分钟） | **不重启** |
| 4 | 进历史页停留 2 分钟（表格阻塞刷新） | **不重启** |
| 5 | 标定零点 / 量程（连续发 get + flash 写） | **不重启** |
| 6 | 恢复出厂（`HAL_Delay(200)` + 写 flash + 复位） | 正常重启一次，屏幕正常 |

★ 若出现**周期性自己重启** ⇒ 窗口太短，需把 `IWDG_RELOAD` 调大（如 6000）或改 `PRESC=64`。
**这种情况请立即告诉我，不要反复上电试。**
