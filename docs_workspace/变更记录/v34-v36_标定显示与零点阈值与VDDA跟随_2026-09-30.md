## 2. v34 · 标定结果显示增强（方案 A）

**动机**：用户提出「零点标定应显示补偿的数值，而不是只显示"标定完成"」。

**改动 6 处**（`Core/Src/main.c`，GBK；脚本 `_fw_cal_display.js`）：

| 位置 | 改后 |
|---|---|
| 零点成功（`cal_report`） | 「零点标定完成 补偿 -xxppm（原始码 xxx）」 |
| 量程成功（对称补全） | 「量程标定完成 灵敏度 x.xx」 |
| 状态行 `cst_s1`（常显） | 「标定：YYYY-MM-DD 补偿-xxppm」（超期态同样带补偿） |
| 缓冲区 | `rs[48]`→`rs[64]`、`s[40]`→`s[56]`（新文案最长 ~58 B） |

**两个避坑决策**：
- `cal_k / cal_b / cal_raw0` 在代码中均为 **int32**（int64 计算后强转）→ 全程 `%d` 打印，**绕开 microlib 不支持 `%f` 的雷**；灵敏度用 `k100=(cal_k+5)/10` 整数化到百分位
- `k100` 声明在 `switch` **之前**（case 内声明变量会编译错）

**验证**：编译 0E/0W；三个新格式串在 `.axf` 中全部命中；真机确认（09-29）零点补偿值与状态行显示正常。
**待验证**：量程灵敏度显示 —— 需 1000 ppm 标气做一次量程标定。

## 3. v35 · 零点浓度上限 20 → 50 ppm

- `CAL_ZERO_MAX_PPM`（`main.c:81`）20 → 50，由用户在 Keil 自改，我方编译归档
- 失败提示「当前超 %d ppm」共用同一宏 → 自动跟随
- **精度影响**：50 ppm 本底对 1000 ppm 满量程为 5%，但零点标定的目的正是补偿它（通洁净空气标定后即被点平）→ 放宽上限**不牺牲精度**，只是让「室内本底略高」的场景不再拒绝标定

## 4. v36 · VDDA 漂移跟随（**正确性改进**；⚠️ 曾被误判为本症状根因，已更正）

### 4.1 现象与排查收敛

| 观测 | 排除了什么 | 指向 |
|---|---|---|
| 主控板电池端子电压：预热期 ≈ 主页期（**无区别**） | 电池/线束/负载压降 | VIN 恒定 |
| 进主页 65% **持续稳定**（非闪现） | 页面重载回控件存储值的短暂窗口 | `g_batt_pct` 真的从 50 变 65 |
| 两个显示控件值源**同为** `g_batt_pct`（代码已核） | 双数据源 / 显示格式差异 | 变的是 `battery_poll` 的读数 |
| 预热期 5 s 爬到 50% 后**55 s 不变** | 读数随机漂动 | 热机电流恒定（真实物理态） |

**收敛结论**：VIN 恒定 + 读数变 = **ADC 换算环节在变** → **VDDA（3.3V 基准轨）随负载漂移**。

```
进主页 → 屏渲染主页（7″ 大背景，电流高于初始化页数百 mA）→ 5V 轨跌
       → 3.3V 级联跟随跌 ≈145 mV（4.4%）
       → ADC code = VIN/VDDA → code 升 4.4%
       → 换算仍用【上电时一次性测定的旧 g_vdda】→ 读数虚高 4.4% → 65%
预热期 → 屏在简单初始化页，负载接近上电校准时刻 → VDDA ≈ 校准值 → 读数准 → 50%
```

**根因定性**：`battery_read_vdda()` **只在 `battery_init()` 测一次**（`battery.c:62-66`）—— VREFINT 用法的经典错误：片内基准的设计目的就是**周期重测**以消除 VDDA 漂移。

### 4.2 修复

- `battery_poll()` 每轮先重测：`g_vdda = battery_read_vdda();`（VREFINT×8，约 2 ms/轮）
- 3 处改动（`BSP/Src/battery.c`，UTF-8；脚本 `_fw_vdda_follow.js`）
