## 1. 现象

| 阶段 | 探头状态文本 | 实际 |
|---|---|---|
| 预热期（初始化页） | **探头 已连接** ✓ | 已连接 |
| 预热期后进入主页 | **探头 未连接** ✗ | 仍已连接 |

（同批受影响的还有主页的**泵文本**与**三个状态圆点** —— 都停在页面文件里的初始文案/图标。）

## 2. 根因：固件自己切页时**没有登记页面状态**

L1（v24）改造后，状态 chips 不再"全页广播"，而是**只发当前页那一套副本**（`sfx`：主页无后缀 / 设置 `_s1` / 历史 `_s2` / 初始化 `_i`）：

```c
465  const char *sfx = "_s1";                 /* 未定页(0xFF)默认发设置页副本, 防漏发 */
466  if (g_page_init)           sfx = "_i";
467  else if (g_page_now == 0u) sfx = "";
468  else if (g_page_now == 2u) sfx = "_s2";
```

而 `g_page_now` **只在屏端导航按钮发 `printh 40/41/42` 时被赋值**（`hmi_on_page_enter`，main.c:1098）。

**固件自己切的页不会产生那个回发** —— 原切页代码只做了三件事：

```c
603  if (g_page_init && (g_skip || !g_warm)) { g_page_init = 0; g_skip = 0; tjc_page(0); }
                                            /* ↑ 没写 g_page_now, 也没置 g_full_dirty */
```

于是切到主页后：

- `g_page_now` 仍是 **`0xFF`（未知）** → 第 465 行兜底走 `sfx = "_s1"` → 芯片被推给**设置页副本**，主页的 `pc0`/`pc0d`/`pc1`/`pc1d` **从未被推送**；
- `g_full_dirty` 也没置 → 连"进页全量补发"这条兜底也没有。

⇒ 主页的探头/泵文本与圆点**停在页面文件里的初始文案**（编辑器里的默认值"探头 未连接"）。

**为什么电量 chip 不受影响**：`battery_poll()` 每 250ms 经 `tjc_set_bat()` **无条件**推 `pc2`/`pc2_s1`/`pc2_s2`，不吃 `sfx`。

**为什么预热期是对的**：`g_page_init=1` 时 `sfx="_i"` 优先级最高，与 `g_page_now` 无关。

## 3. 修复（`main.c`，`_fw_v38_pagestate.js`）

```c
  if (g_page_init && (g_skip || !g_warm)) {
    g_page_init = 0; g_skip = 0;
    g_page_now   = 0;   /* [v38] 固件自己切的页: 屏端不会回发 0x40(那是导航按钮发的), 须自行登记当前页 */
    g_full_dirty = 1;   /* [v38] 进页全量补发: 否则主页 探头/泵 文本+圆点 停在页面初始文案 */
    tjc_page(0);
  }
```

生效路径：该段位于 `app_refresh` 内、**在 `hmi_update_status_chips(full)` 之前**，且 `g_full_dirty=1` 会让 chips 的提前返回失效 → **当轮就以 `sfx=""` 全量补发主页芯片**（下一轮 `full=1` 再补一次，幂等无害）。

### 同时清理的 v37 死代码

用户把初始化页电量文本 chip 由 `pc2_i` **改名为与主页同名的 `pc2`** 后，`tjc_set_bat()` 的**无条件**推送就会覆盖它（TJC 按当前页解析同名对象），v37 加的 `pc2_i` 推送块随之成为**死代码**（目标对象已不存在）。本次一并删除：

- 删除 `s_pct` 静态声明 + 整个 `pc2_i` 推送块（`main.c` 49521 → 49233 B，−288 B）
- `c4f7n_hmi_protocol.h` 的 `OBJ_BAT_CHIP_I` 标注 **[v38 废弃]**（保留定义，注明不再被引用，避免后人再按旧名加代码）

## 6. 附：本次暴露的**同类缺陷模式**（值得记住）

`sfx` 这种"只发当前页副本"的省流量设计，**依赖一个"当前页"状态量**。凡是**不由屏端发起**的页面变化（固件自己 `tjc_page()`），都必须**显式登记该状态量 + 置全量补发**，否则那一页的镜像永远不更新 —— 症状就是"进了新页但显示的是旧页/初始值"。

（v37 的电量冻结是同一族的另一面：**"变化才发"的提前返回**把某个连续量的推送挡在了门外。）
