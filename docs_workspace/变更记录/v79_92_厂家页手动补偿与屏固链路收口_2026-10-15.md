## 一、功能

厂家设置页（屏页 ID 5 / `2.pa`）新增「零点补偿 b」与「增益补偿 k」两项手动补偿。

```
改 b / k → 点「校B」/「校K」 → 固件 get 回读 → 校验 → 落盘 → 推屏
```

| 项 | 说明 |
|---|---|
| **零点补偿 b** | ppm 偏置，管零点准不准。范围 **±200 ppm**，整数，可负 |
| **增益补偿 k** | 比例系数，管满量程准不准。范围 **0.1x~10.0x**，屏上按**百分比**显示 |
| 数据流 | 屏端键盘输入 → `printh D5 5A 21/22` → ISR 置标志 → 主循环 `tjc_get` 回读 → 钳位/二次确认 → `param_save` → `man_apply()` |
| 生效值 | `man_eff_k/b()` = 手动值（非 0）否则回落标定值；两者在 Flash 里**分离存放，互不覆盖** |
| 量程标定 | **手动值优先**：`cal_do_span()` 里 `if (!PP.man_k) PP.cal_k = k;` —— 已有手动 k 时只解 b 做零点平移 |
| 公式（屏上静态显示） | `ppm = raw x k/1000 + b`，钳位 `0~1500` 在所有修正之后**只发生一次** |

### 屏端控件（v12）

| objname | 类型 | 坐标 | 说明 |
|---|---|---|---|
| `cb` / `ck` | **数值控件** `type=54` `key=2` `vscope=1` | (300,410)/(300,460) 100×40 | ⚠️ 数值控件**只能写 `.val`**，写 `.txt` 被忽略 |
| `cbv`/`ckv`/`cbv2`/`ckv2` | 文本 `type=116` | (45,410)/(45,460)/(400,410)/(400,460) | 标签：零点补偿b / 增益补偿k / ppm / % |
| `bcb` / `bck` | 按钮 `type=98` | (45,516)/(155,516) 100×40 | up 事件发 `printh D5` / `printh 5A` / `printh 21|22` |
| `cfc` | 文本 `type=116` | (542,410) 420×40 | 公式 `ppm = raw x k/1000 + b` |

id 重排 0..49 连续；`endx/endy` 全部核对为 `x+w-1` / `y+h-1`；最高点 y+h=590 < 屏高 600。

### 安全阀

- **二次确认**：k 变化 > 20% 需再按一次「校K」。判据是「**读回值 == 暂存值**」（无时间窗口）。
- **越界拒绝**：超范围时**拒绝并回推原值 + 提示**，不做静默钳位（静默会让用户以为设成功）。
- ⚠️ `man_b==0` 是「未手动」哨兵 ⇒ **无法表达「强制归零」**，需要另加 valid 标志位。

| 版 | 症状 | 真因 |

| **v91** | **b/k 都要点两三次** | **ISR 内发串口与主循环报文在线交织** ⇒ 屏端解析器错位吞掉后续字节；而握手层对裸码「绝不执行」⇒ 丢一字节=丢一次点击 |
| v92 | — | 摘除临时诊断（指令计数 `#N`），保留 v91 的延后发送机制 |

### 沉淀为硬约束（已写入 `AGENTS.md` §4.5 与 `HANDOVER.md` §10.6）

1. **get 回包路由判据** = 谁**确实发出过 get 且还没收到回包**（`g_*_wait`），不是谁有请求在等（`g_*_req`）。
2. **UART 的 TX 只允许来自主循环**。`HAL_UART_Transmit` 阻塞但可被中断抢占 ⇒ ISR 发串口会与主循环报文在线交织。
3. **多通道轮询函数**：本通道收尾 + 对外可见上报，必须排在所有「让出给别的通道」的 `early-return` **之前**。
4. **新增 `D5 5A NN` 命令码必须同时改三处**：协议头枚举 / `switch` case / **`s_guard_list[]` 白名单**。
5. **「点几次才生效」先怀疑链路层丢消息**。排查顺序：① 命令有没有到达 → ② 回包有没有回来 → ③ 分支判据对不对。
6. **抄骨架要连「状态初始化」那一半一起抄**（漏了「计时基准在请求处赋值」就让 get 从未发出过）。
7. **时间窗口是反模式** —— 能用「数据是否变化」表达的确认，不要用「时间」表达。
