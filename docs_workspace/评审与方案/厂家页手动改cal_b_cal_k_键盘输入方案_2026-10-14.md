# 厂家设置页「手动修改 cal_b / cal_k」设计方案

> 日期：2026-10-14 ｜ 状态：**待用户确认后实施**（本文不落地任何代码）
> 需求：在厂家设置页**用屏幕键盘手动输入** `cal_b`（ppm）与 `cal_k`（‰）的数值。

---

## 一、方案定位

与前一版「± 步进微调」不同，本版是**直接输入任意数值**，灵活性更高，
也更贴合「标定后仍需微调」的实际场景。

**复用项目已有的成熟模式**：阈值 `h.val` 就是「屏端键盘输入 → 固件 `tjc_get` 回读 → 钳位后落盘」
（`main.c:1202-1229`）。本方案沿用同一套骨架，不发明新机制。

---

## 二、界面设计

### 2.1 控件清单（厂家页 `2.pa` 现有 41 个对象，新增 5 个）

厂家页 `y=400` 以下为空区（`p0` 已删），布局与上方完全同构：

| 名称 | type | 位置 | 作用 |
|---|---|---|---|
| `cbv` | 116 (文本) | 45,420 200×40 | 标签「零点补偿 b」 |
| `cb` | 54 (数值) | 300,420 100×40 | **显示 + 输入** `cal_b` |
| `ckv` | 116 (文本) | 45,470 200×40 | 标签「增益补偿 k」 |
| `ck` | 54 (数值) | 300,470 100×40 | **显示 + 输入** `cal_k` |
| `bcb` | 98 (按钮) | 410,420 90×40 | 「校B」→ 调起键盘改 b |
| `bck` | 98 (按钮) | 410,470 90×40 | 「校K」→ 调起键盘改 k |

⚠️ **`cal_k` 是千分比**（1000 = 1.000），直接让用户输「923」不直观。
两种选择见 §4.2。

### 2.2 为何用 `type=54`（数值控件）而非文本

- 数值控件自带 `vvs=0`（整数）与上下限属性，可直接显示数字；
- **可调起系统键盘**：与 `h`（阈值输入）同构，实测可行；
- 固件用 `tjc_get(OBJ, "val")` 回读，走 `get` 通道（与 `hmi_get` 共用，有互斥保护）。

## 三、交互流程（复刻阈值输入）

```
用户点「校B」
   ↓ 屏端 cb 调起系统键盘 → 用户输入数字 → 按OK
   ↓ 屏端 printh D5 / printh 5A / printh <码>
   ↓ 固件 ISR 置标志（不阻塞）
   ↓ 主循环轮询: tjc_get("cb", "val")  ← 带 500ms 超时 + 8000ms 耐心窗口 + 重试
   ↓ 钳位到合法范围
   ↓ 落盘 param_save_safe()
   ↓ 回推 crs_f 显示结果
```

**固件侧完全复用阈值那套**（`g_thr_hi_req` / `g_get_busy` / `g_thr_wait` / `g_thr_deadline`）。
建议**独立一套标志位**（`g_calb_req` / `g_calk_req`），不要与阈值共用 ——
否则用户在两页同时操作会互相抢占 `g_get_busy`。

### 3.1 命令码

协议头空位：`0x18`、`0x19`、`0x21`、`0x22` 均未占用。

```c
HMI_CMD_CAL_B_SET = 0x21,   /* 键盘改 cal_b 完成 → 请 MCU 回读 cb.val */
HMI_CMD_CAL_K_SET = 0x22,   /* 键盘改 cal_k 完成 → 请 MCU 回读 ck.val */
```

⚠️ **必须走三字节握手** `D5 5A NN` + 三态状态机。
依据：屏口（USART3）**逐字节无过滤匹配命令码**，实测噪声非均匀（`0x1A` 占 23.8%），
2 字节握手仍有 0.117% 误触发率（每 1380 次），**3 字节才 0 次**。
参考现有实现：`cf`（恢复出厂）已改单发 `D5 5A 17`。

## 四、核心设计决策

### 4.1 范围钳位（必须做）

| 参数 | 范围 | 理由 |
|---|---|---|
| `cal_b` | **−500 ~ +500 ppm** | 超过 ±500 说明传感器异常，不是补偿问题 |
| `cal_k` | **100 ~ 10000**（0.1x ~ 10.0x） | 与 `SENSOR_CAL_K_MIN/MAX` 一致 |

⚠️ **钳位必须做**：这两个值直接决定浓度读数，一个手滑的输入就能让设备全程读数错误。

### 4.2 `cal_k` 的显示单位（需你选）

| 方案 | 屏上显示 | 用户输入 | 换算 |
|---|---|---|---|
| **A. 直接显示千分比** | `923` | 923 | `cal_k = 923` |
| **B. 显示为百分比** | `92.3%` | 92.3 | `cal_k = 输入 × 10` |

**推荐 B**：`92.3%` 对用户直观（"传感器读数偏高 10%，那系数就是 92.3%"），
而 `923` 需要理解"千分比定点"这个内部实现细节。
⇒ 选 B 则固件回读后 `cal_k = (int32_t)(v * 10)`，且要处理小数输入（TJC 键盘支持 `.`）。

### 4.3 ★ 与标定流程的冲突（最重要的一点）

**`cal_do_span()` 会无条件写 `PP.cal_k` 和 `PP.cal_b`**（`main.c:1474-1475`）：

```c
PP.cal_k = (int32_t)k;      /* 无条件覆盖 */
PP.cal_b = (int32_t)b;      /* 无条件覆盖 */
```

⇒ **用户手动调好 b/k 后，只要再做一次量程标定，手动值就会被冲掉。**

三种处理方式：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 接受冲掉** | 文档提示「标定会重置手动值」 | ⚠️ 用户会认为功能有 bug |
| **B. 标定后重放** | 保存手动值，标定完再叠加回去 | ⚠️ 叠加语义混乱（该加还是该乘？） |
| **C. 明确优先级** | **手动值优先**：若存在手动值，量程标定时**只解 raw0，不动 k** | ✅ 推荐 |

**推荐 C**，理由：
- 量程标定的价值是解 `k`；若用户已手动定过 `k`，说明他已掌握现场真实比例，
  固件不该覆盖；
- 实现上只需在 `cal_do_span()` 开头加一个判断：`if (手动值存在) { 只用 cal_b 点平 }`，
  逻辑清晰，不影响现有标定流程；
- 需在界面上标注「手动模式下，量程标定仅做零点平移」。

### 4.4 落盘策略

| 项 | 决定 | 理由 |
|---|---|---|
| 手动值存哪 | **`param_t` 新增两个字段** `man_b_valid` / `man_k_valid` | 与标定值分离，标定不丢手动值 |
| 是否新增字段 | ✅ 需要（`PARAM_VERSION` 3 → 4） | 版本号必须升，否则旧数据 CRC 校验会误判 |
| 恢复出厂 | 手动值**一并清零** | 与 `dump_defaults` 天然一致 |
| 清空历史 | **不清**（手动值与历史无关） | 同 `hist_base` 现有处理 |

⚠️ **`PARAM_VERSION` 必须升到 4**。`param_store.c` 的 `param_load` 会校验 version，
不匹配则填默认值 —— 不升版本会让新字段变成随机值。

## 五、界面显示同步

### 5.1 谁写这两个数值

固件是唯一写入方（屏端不碰），在进厂家页时随 `cst_f` 一起推：

```
进入厂家页 (printh 45)
   ↓ 主循环 app_refresh, g_page_now==5
   ↓ g_cal_st_dirty = 1
   ↓ 推 cst_f("已标定 2026-10-14 补偿 -100ppm")
   ↓ 推 cb.val = (手动b有效? 手动b : cal_b)
   ↓ 推 ck.val = (手动k有效? 手动k/10 : cal_k/10)
```

### 5.2 标签内容要区分来源

`cst_f` 文案建议扩成：

| 状态 | 文案 |
|---|---|
| 无手动覆盖 | 「已标定 2026-10-14 b=-100 k=92.3%」 |
| 有手动覆盖 | 「已标定 2026-10-14 b=-80* k=90%」+ `*` 表示手动 |

★ **必须让用户一眼看出「现在生效的值是标定的还是手动的」**，否则无法判断标定有没有被冲掉。

## 六、安全阀（不可省）

`cal_k` 直接决定读数，一个错误输入 = 设备全程读数错误。

1. **双重确认**：`cal_k` 改动后，若新值与旧值差 > 20%，要求二次确认
   （沿用 `CAL_ZERO_CONFIRM_MS` 两步确认范式，`crs_f` 显示「确认生效？」）；
2. **越界提示**：输入超范围时**拒绝并回推原值** + `crs_f` 提示「超出允许范围」，
   **不做静默钳位**（静默钳位会让用户以为设成功了）；
3. **超差警告**：新 `k` 导致 1000ppm 点预期误差 > 5% 时，在 `crs_f` 提示
   「建议重新量程标定」。

## 七、屏端改动清单（实施时由用户在编辑器操作）

### 7.1 新增 6 个对象（`2.pa` 厂家页）

⚠️ **`.HMI` 禁止脚本改写**（10-13 三连败），必须用户在 TJC 编辑器里手工添加。

| 名称 | type | x,y | w,h | 注意 |
|---|---|---|---|---|
| `cbv` | 文本 | 45,420 | 200×40 | txt="零点补偿b" |
| `cb` | 数值 | 300,420 | 100×40 | **vvs=0**，key=2（键盘风格） |
| `cbv2` | 文本 | 510,420 | 200×40 | txt="ppm"（单位提示） |
| `ckv` | 文本 | 45,470 | 200×40 | txt="增益补偿k" |
| `ck` | 数值 | 300,470 | 100×40 | **vvs=0**，key=2 |
| `ckv2` | 文本 | 510,470 | 200×40 | txt="%"（单位提示） |

⚠️ **改坐标必须同步 `endx`/`endy`**（`=x+w-1` / `=y+h-1`，闭区间）。
这是**实际命中边界**，不同步则命中区停在旧位置、**零报错**（v62 实战 4 个按钮全点不动）。
★ 排查这类问题「算一遍」比「比一遍」有效：同源克隆对象的属性天然一致，逐属性 diff 看不出。

⚠️ 新对象 `id` 必须连续（现有 41 个 ⇒ 新增后 47）。克隆对象时**必须重排 id**，
否则 load 找不到控件 / 编辑器报 `objedit ref error`。

⚠️ `key` 属性：官方说明 N 是「键盘风格」选择项，**编辑器保存时恒写回 2**，不要手改。

### 7.2 两个按钮的脚本

`bcb`（校B）：
```

codesup-3
printh D5
printh 5A
printh 21

★ **屏端不要自己回写 `cb.val`** —— 由固件经 `tjc_get` 回读后统一推送（与 `h` 同构）。

`bck`（校K）：
```

### 7.3 键盘页的返回

系统键盘由 `cb.key` / `ck.key` 自动调起，**不需要用户写代码**。
按 OK 后屏端执行「回调到 `cb` 的 up 事件」，在 up 里发命令码。

## 九、需要你确认的 5 个决策点

1. **`cal_k` 显示单位**：直接显示千分比 `923`，还是百分比 `92.3%`？（推荐百分比）
2. **标定冲突**：采用 §4.3 的 C 方案（手动值优先，量程标定只做零点平移）吗？
3. **步进**：需要「± 微调」按钮吗，还是只要键盘输入？（键盘输入已经够用，可省 4 个按钮）
4. **双重确认阈值**：新 `k` 与旧值差多少需要二次确认？（建议 20%）
5. **取值范围**：`b` ±500ppm、`k` 0.1x~10.0x 是否合适？

确认后我再出逐字的屏端清单 + 固件实现。
