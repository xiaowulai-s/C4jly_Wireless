# 标定与恢复出厂 · 内部流程与关联信息

> 基线：屏 `C4F7N_v4_fix11b.HMI` / 固件 `C4F7N_v20_firmware.hex`（2026-09-22）
> 代码位置：屏端 `5.pa`、`Program.s`；固件 `Core/Src/main.c`、`BSP/Src/sensor.c`、`BSP/Src/param_store.c`

## 0. 一句话概括

三个按钮走**同一条链路**：屏端 `printh` 命令码 → 固件回调 → 前置校验 + 换算 → **擦写 W25Q64 扇区 0** → 回写屏文案。恢复出厂额外多一步**整机复位重启**。

---

## 1. 屏端入口（设置页 5.pa）

位置：`y=410` 是标签文字，`y=450` 是按钮（各 100×40 px）

| 标签 | 标签对象 | 按钮 | `codesup` 脚本 | 发送 |
|---|---|---|---|---|
| 零点标定 | `czl` | `c0` | `c0.txt="执行中"` → `printh 15` | **0x15** |
| 量程标定 | `csl` | `c1` | `c1.txt="执行中"` → `printh 16` | **0x16** |
| 恢复出厂 | `cfl` | `cf` | 两段确认（下） | **0x17** |

初始文案分别是 `执行` / `执行` / `恢复`（GBK）。

### `cf` 的两段确认（12 行脚本）

```
cft=cfs
cfs=0
if(cft==0)
{
cfs=1
cf.txt="确认"
}
if(cft==1)
{
cf.txt="恢复"
printh 17
}
```

- **第 1 次点**：`cfs` 0→1，按钮文字变「确认」（进入待确认）
- **第 2 次点**：`cfs` 1→0，文字回到「恢复」，并发出 `0x17`
- `cfs` / `cft` 是 `Program.s` 声明的全局变量（`int ... cfs=0,cft=0`）
- ✅ **防误触**：5.pa 页根 `codesload` 末段有 `cfs=0` → 离开/重进设置页自动解除待确认
- ⚠️ 但 `cf.txt` 文案**没有**在 load 里复位 → 若点了第一次就切页，回来时文字仍是「确认」

## 2. 固件侧处理

### 2.1 零点标定 `hmi_on_cal_zero()`（main.c L768）

| 步 | 动作 |
|---|---|
| 1 | `ppm = sensor_read_ppm()` — 取**已校准**后的值 |
| 2 | `if (ppm >= ZERO_CAL_THRESHOLD_PPM /*=20*/)` → `c0.txt="失败"`，**放弃** |
| 3 | `raw = sensor_read_raw()` — 取**未校准**原始值 |
| 4 | `sensor_get_cal(&k,&b)` → **保留原斜率** `PP.cal_k = k` |
| 5 | `PP.cal_b = (int32_t)(-raw)` — 使当前 raw 对应 **0 ppm** |
| 6 | `PP.cal_valid = 1` |
| 7 | `param_save(&PP)` — **擦扇区 + 写回** |
| 8 | `sensor_set_cal(PP.cal_k, PP.cal_b)` — 更新 RAM 镜像 |
| 9 | `c0.txt="执行"` |

判据常量：`ZERO_CAL_THRESHOLD_PPM = 20`（main.c L59）
含义：**只在洁净空气（<20ppm）下**才允许零点标定。

### 2.2 量程标定 `hmi_on_cal_span()`（main.c L782）

| 步 | 动作 |
|---|---|
| 1 | `ppm` 必须在 **900 ~ 1100**（`SENSOR_SPAN_PPM=1000` 的 ±10%），否则 `c1.txt="失败"` 返回 |
| 2 | `raw = sensor_read_raw()`；`if (raw <= 0.0f) return;` ⚠️ **静默返回，不改文案** |
| 3 | `m = (1000 - PP.cal_b) × 1000 ÷ raw`（**64 位整数运算**） |
| 4 | 钳位到 `SENSOR_CAL_K_MIN=100` ~ `SENSOR_CAL_K_MAX=10000` |
| 5 | `PP.cal_k = m; PP.cal_valid = 1` |
| 6 | `param_save(&PP)` → `sensor_set_cal(...)` → `c1.txt="执行"` |

**公式依据**（sensor.c）：`ppm_out = raw × cal_k / 1000 + cal_b`
→ 令 `ppm_out = 1000`（标定气浓度）、`raw` 为实测原始值，解出
`cal_k = (1000 − cal_b) × 1000 ÷ raw` ✓ 与代码一致

> ⚠️ 量程标定**依赖先做零点标定**（用到 `cal_b`）。若 `cal_b=0` 直接做量程，斜率会偏。

### 2.3 恢复出厂 `hmi_on_cal_factory()`（main.c L800）

| 步 | 动作 |
|---|---|
| 1 | `param_factory(&PP, 1)` — 填默认值 + **立即写 flash** |
| 2 | `g_thr_hi = PP.thr_hi; g_thr_lo = PP.thr_lo;` |
| 3 | `sensor_set_cal(PP.cal_k, PP.cal_b)` |
| 4 | `app_apply_threshold()` — 把新高报阈值下发到屏 `h.val` |
| 5 | `HAL_Delay(120)` — 延时等屏显示 |
| 6 | **`NVIC_SystemReset()`** — 整机复位重启 |

④⑤⑥ 的后果：**重启后走正常启动流程**（初始化页 → 60s 预热 → 主页），
屏上 `c0/c1/cf` 文案与 `h` 数值都随之刷新。

## 3. 唯一真源：W25Q64 扇区 0

扇区规划（param_store.h）：扇区 0（4KB）= 标定 + 设置；扇区 1~2047 = 历史数据。

`param_t` 结构（32 B，小端）：

| 字段 | 类型 | 默认值（`dump_defaults`） |
|---|---|---|
| `magic` | uint32 | `0xC4F74A55` |
| `version` | uint32 | `2` |
| `cal_k` | int32 | `1000`（= 1.000，0.001 定点） |
| `cal_b` | int32 | `0` |
| `thr_hi` | uint16 | `500` |
| `thr_lo` | uint16 | `100` |
| `buzzer_en` | uint8 | `1`（蜂鸣器开） |
| `unit_mode` | uint8 | `0`（ppm） |
| `cal_valid` | uint8 | `0` |
| `crc` | uint32 | XOR 旋转校验 |

**写盘方式**：`param_save()` = 整扇区（4KB）擦除 → 写回 32 B（含重算 CRC）
**上电加载**：`param_init()` 读回 → 校验 `magic` / `version` / `crc`，任一不符则填默认值并写回

### 三层镜像关系

| 层 | 载体 | 谁写 |
|---|---|---|
| Flash | W25Q64 扇区 0（`param_t`） | `param_save`（零点/量程/出厂/阈值延时保存） |
| RAM 结构体 | `param_t PP`（main.c） | 上述回调 + 阈值加减 `thr_commit()` |
| RAM 标定镜像 | `s_cal_k` / `s_cal_b`（sensor.c static） | 只由 `sensor_set_cal()` 更新 |

`param_save()` 的全部调用点：

| 触发 | 位置 |
|---|---|
| 零点标定 | main.c L776 |
| 量程标定 | main.c L794 |
| 恢复出厂 | param_store.c L64（`save_now=1`） |
| 阈值加减后 **200ms 延时保存** | main.c L357（`g_save_pending` 去抖） |

## 4. 关联但**不受**这三项影响的信息

| 项 | 说明 |
|---|---|
| **历史记录** | 在扇区 1~2047，**恢复出厂不清**（全码检索无 `history_clear/erase/reset/format`） |
| **RTC 时间** | 屏硬件 RTC 自行走时，**不由固件或本流程改写** |
| 屏背光 `dim` | 由屏自己保存（`Program.s` 注释明确「背光跟随已保存的 dim」），不属 `param_t` |
| 泵状态 / 静音 / 峰值统计 | 恢复出厂**不显式复位**；但紧接着整机复位，重启后自然归零、泵默认停止 |
| 屏端 `cfs` 待确认态 | 进设置页即清 0（load 脚本） |
| 屏端 `h` 显示值 | 不是独立数据，是固件 `g_thr_hi` 的投影（`app_apply_threshold`） |

## 5. 现存问题 / 待确认

| # | 问题 | 影响 | 级别 |
|---|---|---|---|
| 1 | `unit_mode` **从没被读** | 恢复出厂「单位复位」无实际效果 | 🟡 死字段 |
| 2 | `cal_valid` **只在标定时写、从没被读** | 无"是否已标定"判断；用过坏系数也不提示 | 🟡 死字段 |
| 3 | 零点 `PP.cal_b = (int32_t)(-raw)` **截断小数** | 标定残差可达 <1 ppm | 🟡 精度 |
| 4 | 量程标定 `raw <= 0` **静默 return** | 按钮永久停在「执行中」，无失败提示 | 🟠 UI |
| 5 | `cf.txt` 未在页 load 复位 | 点一次后切页回来仍显示「确认」 | 🟠 UI 误导 |
| 6 | 零点/量程标定**无"标定中"限制** | 标定期间若踩到其它按钮/断电，无保护 | 🟡 健壮性 |
| 7 | 量程标定**无处输入标定气浓度** | 浓度写死 `SENSOR_SPAN_PPM=1000`；换标定气需改宏重编 | 🟠 设计 |

> 另：屏端 `l`（低报阈值）与 `0x04/0x05` 已于 fix11 删除，`thr_lo` 只能靠恢复出厂回默认值 100，**当前无常规调节入口**。
