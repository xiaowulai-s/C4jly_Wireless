## 问题 ① 开机电量递加（56% → 67%）

### 机制（两层叠加，显示链本身忠实）

**显示形态层**（"不连续递加"的观感）：
- `battery_init()` 首采**直通**（`g_filt_first` 低通直通 + 量化滞回 `shown` 直通，battery.c:108/561 区）—— 上电瞬态读数被定格为显示起点
- 之后量化滞回每 poll 最多 +1%（250ms 一格 = **4%/s**）→ 阶梯式递加
- `main.c:343/344` battery_init + poll 在 main 初始化早期（屏未就绪、传感器刚上电）

**数值来源层**（为什么起点低、终点高）：
- 56% ↔ 14.41V，67% ↔ 14.88V，差 **0.47V** —— 远超低通收敛尾差（低通 2s 内收敛完），**读数源（电池端电压）在开机后真实爬升**
- 最大嫌疑：**GC5G1 NDIR 热机负载** —— 传感器上电光源/加热浪涌 → 电池端电压被内阻拉低 → 预热期稳定在低值（56%）→ 预热结束负载回落 → 电压回升（67%）
- 即：**56% 和 67% 都是当时的真实端电压**，显示没有说谎；"问题"在于把热机瞬态当有效显示

### 改进方向（暂不实施）

- 预热期电量遮罩：初始化页电量 chip 显示 `--`（或首采后延迟 N 秒再显示），热机稳态后才出真实值 —— 与浓度 `--` 的遮罩哲学一致
- 或首采改为"N 次采样取中值"规避上电瞬态（但治标）

### ★ 09-30 三次补充（**定案更正**）：真因是「推送被冻结」，不是 VDDA

**排除 VDDA 的决定性证据**：用户实测 —— 两种状态**主控板电池端子电压无区别**（电压没变）；且 v36 烧录后**症状依旧**。

**真正根因（代码级，证据闭合）**：`main.c::hmi_update_status_chips()` 中，初始化页电量文本 `pc2_i` 的推送块（**479-484 行**）**位于第 463 行「圆点档位缓存」提前返回之后**：

```c
461  uint8_t bpic = (pct >= BAT_DOT_WARN_PCT) ? GREEN : (pct >= BAT_DOT_LOW_PCT) ? AMBER : RED;
     /* BAT_DOT_WARN_PCT = 50 ; BAT_DOT_LOW_PCT = 20  (c4f7n_hmi_protocol.h:96-97) */
463  if (!g_full_dirty && !full && dot == s_dot && pump == s_pump && bpic == s_bat) return;   /* ← 档位不变即返回 */
...
479  if (g_page_init) { ... tjc_set_txt(OBJ_BAT_CHIP_I, "电量 N%") ... }                        /* ← 到不了 */
```

`bpic` 是**三档圆点颜色**（≥50 绿 / ≥20 橙 / 其余红），**不是 pct**。预热期 pct 从 ~30% 爬到 65% 的全程里，`bpic` **只在 pct 跨过 50 那一瞬变一次**：

- pct 跨 50 → `bpic` 橙→绿 → 不 return → 执行到 484 行 → `pc2_i` 被写成「**电量 50%**」
- pct 继续 50→65 → `bpic` 恒为绿 → 每轮 463 行 return → **`pc2_i` 永久冻结在 50%**

**与全部观测逐条吻合**

| 观测 | 解释 |
|---|---|
| 预热期"不连续递加"后**冻结在 50%**（恰好等于阈值） | 只在离散事件（上电 `full` 补发 / 探头上线 `dot` 变化 / pct 跨 50）时才推一次；50 以上档位不变 → 不再推 |
| 进主页立刻 65% 且**持续稳定** | 主页 chip `pc2` 由 `tjc_set_bat()` **每 250ms 无条件推送** → 真实值 |
| 两态端子电压**无区别** | **电压本来就没变** —— 问题在"推送"不在"测量"（决定性反证） |
| v36（VDDA 每轮重测）**无效** | VDDA 从来不是本症状的原因 |

**回归来源**：**L1 改造（v24 / 2026-09-24）引入** —— L1 之前 chips 每轮无条件全发，`pc2_i` 实时更新；L1 加"变化才发"缓存后，`pc2_i` 的更新块被套在**不相关**的圆点档位缓存之后。

**修复方案（待确认；约 10 行，纯 `main.c`）**：把 `pc2_i` 推送提到提前返回**之前**，并给它**自己的门**（pct 变化）：

```c

  if (!g_full_dirty && !full && dot == s_dot && pump == s_pump && bpic == s_bat) return;
```

## 问题 ② 预热页时间闪烁（初始时间 ↔ 实际时间 2~3 次）

### 机制（高置信，实锤）

**两个渲染源交替**：
- **A（真实时间）**：初始化页 `tim` 定时器脚本 `rY_i.val=rtc0 … rsec_i.val=rtc5`（屏硬件 RTC，每拍自刷）
- **B（初始时间）**：**页面存储值** —— rY_i 等 type=54 控件保存着设计时输入的初始值；**页面每次加载/重载都会按存储值重渲染**

**重载源**：固件上电竞态双路修复（v18）—— `main.c:364/367/369` **连发三次 `tjc_page(3)`**（首发 + 1.5s + 2.5s 补发），叠加屏端 `Program.s` 自己的上电加载页，初始化页**共被加载 4 次**。每次重载：控件回存储初始值（B）→ `tim` 下一拍刷回真实时间（A）→ 循环。**3 次补发 = 2~3 次闪变**，与观察完全吻合；补发完成后 `tim` 持续自刷 → 稳定。

**固件侧无责佐证**：固件对屏 RTC **只读不写**（`rtc_time_start_sync` 仅发读请求，`finalize` 只设 MCU 侧 epoch；grep 全文无 `rtc0=` 写命令）。

### 改进方向（暂不实施）

- 补发完成后**强制刷一次时间**（固件无 rtc 写权限 → 屏端做：`tim` 周期缩短，或在页面 `load` 事件里直接执行一遍同样的 6 行赋值 —— **推荐后者**，页面每次加载立即出真实时间，不依赖第一拍 timer）
- 或补发策略优化：确认屏已就绪后再补发（需屏回执，改动大）
- 注意：三次补发是"上电竞态"修复（屏冷启动吞指令），**不能简单删掉** —— 屏端 load 脚本方案可两全

## 问题 ③ 开机满量程报警（接烧录器持续 / 不接可跳过）

### 固件侧排除（重要结论）

**预热期固件逻辑上不可能触发报警**：
- `app_refresh` 中 `g_warm` 强制段（main.c:601）在报警判定（626-629）**之前**：预热期每轮 `g_ppm=0, g_alarm=0`
- `tjc_alarm_on()` **全工程唯一调用点**在 main.c:639，被 `g_alarm>=2 && PP.buzzer_en` 门控
- main 初始化段（含 3 次 `tjc_page(3)`）期间主循环未启动，固件无任何 play
- → **开机几秒的报警声不是固件喇叭输出**

### 声源最大嫌疑：传感器模组自带蜂鸣（上电自检）

- NDIR 模组（MST-N7M）普遍带**上电自检蜂鸣**（自检失败时持续报警 + 输出满量程值是常见行为）—— 需查麦芽规格书"上电行为"章节确认
- "接烧录器"的差异 = **上电时序/供电拓扑变化**：ST-Link 的 3.3V 与设备 3.3V 并联（若 VREF 相连）→ 传感器上电时序/地电位改变 → 模组自检异常（持续报警/满量程输出）；预热结束（`g_warm=0`）后若传感器仍输出满量程，固件**真实报警**（这是正确行为，问题在传感器读数）

### 定位实验（3 个，无需改固件）

1. **只接烧录器（不接电池）开机**：若同样满量程报警且持续 → 烧录器供电下传感器异常，实锤供电拓扑影响
2. **断开传感器 TX 线（保留供电）开机**：若几秒的报警声仍在 → 声源是模组自身蜂鸣（固件无责）；若消失 → 声源需重新定位
3. **跳过预热进主页看 `cc` 读数**：接烧录器时若显示 1500（满量程）→ 传感器在烧录器供电下持续输出满量程值（数据侧异常）；跳过后读数正常 → 仅上电几秒瞬态

### 改进方向（定位后）

- 若模组自检蜂鸣：固件可在 `g_warm` 期发 `tjc_dim`/提示语遮掩（无法关模组蜂鸣）；或硬件上模组选型时要求"可配置关闭自检报警"
- 若 SWD 3.3V 并联冲突：烧录时规范"先接 SWD 后上电池"或断开 ST-Link VREF 供电跳线

## 4.4 问题④ 进主页后探头/泵/圆点停在初始文案（09-30 新增，已修复 = 固件 v38）

**现象**：预热期（初始化页）探头显示"已连接"；预热结束进主页后显示"**未连接**"，实际探头已连接。同批受影响：主页泵文本 + 三个状态圆点。

**根因：固件自己切页时没有登记页面状态**（与 v37 同族 —— 都是 L1 "只发当前页副本" 设计的状态缺失）

```c
465  const char *sfx = "_s1";                 /* 未定页(0xFF)默认发设置页副本, 防漏发 */
466  if (g_page_init)           sfx = "_i";
467  else if (g_page_now == 0u) sfx = "";
468  else if (g_page_now == 2u) sfx = "_s2";
```

`g_page_now` 只在**屏端导航按钮**发 `printh 40/41/42` 时被赋值（`hmi_on_page_enter`，main.c:1098）。
**固件自己 `tjc_page(0)` 切页不会产生该回发** → 切页后 `g_page_now` 仍是 `0xFF` → 第 465 行兜底走 `sfx="_s1"` → 芯片推给**设置页副本**，主页的 `pc0`/`pc0d`/`pc1`/`pc1d` **从未被推送**；`g_full_dirty` 也没置 → 进页补发这条兜底也没有 → 停在页面文件初始文案。

**为什么电量 chip 不受影响**：`battery_poll()` 每 250ms 经 `tjc_set_bat()` **无条件**推 `pc2`/`pc2_s1`/`pc2_s2`，不吃 `sfx`。
**为什么预热期是对的**：`g_page_init=1` 时 `sfx="_i"` 优先级最高，与 `g_page_now` 无关。

**修复（v38）**：

```c
  if (g_page_init && (g_skip || !g_warm)) {
    g_page_init = 0; g_skip = 0;
    g_page_now   = 0;   /* [v38] 固件自己切的页: 屏端不会回发 0x40, 须自行登记当前页 */
    g_full_dirty = 1;   /* [v38] 进页全量补发: 否则主页 探头/泵 文本+圆点 停在页面初始文案 */
    tjc_page(0);
  }
```

该段位于 `app_refresh` 内、chips 调用**之前**，且 `g_full_dirty=1` 使 chips 的提前返回失效 → **当轮即全量补发主页芯片**。

**验证**：0 Error / 0 Warning；Code 38396 → **38380**；RO-data 1616 → 1600（删掉的格式串）；hex 2509 行校验 0 错，md5 `7e9339e5`；归档 `C4F7N_v38_firmware.hex`。
**同批清理**：用户把初始化页电量文本 chip 改名 `pc2` 后，v37 的 `pc2_i` 推送块成为死代码 → 删除（`main.c` −288 B），`OBJ_BAT_CHIP_I` 标注废弃。
**真机结论**：进主页后探头/泵文本与三圆点显示正确（不再停在初始文案）—— **✅ 09-30 验证通过**。拔探头路径走"值变化才发"，本次未单独回归（与本次改动无关）。

**★ 暴露的缺陷模式（同族第二条）**：`sfx` 这类"只发当前页副本"的省流量设计**依赖一个"当前页"状态量**；凡是**不由屏端发起**的页面变化（固件 `tjc_page()`），都必须**显式登记该状态量 + 置全量补发**。
