# 排查：预热期点"跳过"后浓度显示 0 而非 `--`

> 2026-09-24 真机发现（真机联调通过后的遗留项）。**只排查，未实施修复。**

## 1. 现象

预热期（上电 60s 遮罩内）在初始化页点隐藏跳过按钮 → 进入主页 → 浓度大字 `cc` 显示 **0**（应为 `--`）。

## 2. 根因（一行版）

**`cc` 是数字控件（type 54），只有 `.val`、没有可显示的 `.txt`** —— 固件里负责显示 `--` 的那句 `tjc_set_txt(OBJ_CONC, "--")` 从 09-22 起**一直被屏端静默忽略**；预热期 `app_refresh()` 又每 250ms 无条件推 `.val = g_ppm = 0`。跳过只是让 `cc` 第一次变得可见。

## 3. 证据链（全部带行号，可复核）

### 3.1 固件 `C4F7N_Demo/Core/Src/main.c`（GBK）

```c
/* 522~531 行（app_refresh，250ms 周期） */
g_ppm = sensor_read_ppm();
g_warm = ((HAL_GetTick() - g_boot_ms) < BOOT_INIT_MS) ? 1 : 0;
if (g_warm) { g_ppm = 0.0f; g_alarm = 0; }   /* 预热期强制浓度=0 */
/* 跳过/预热结束 -> 切主页(页0)，仅一次 */
if (g_page_init && (g_skip || !g_warm)) { g_page_init = 0; g_skip = 0; tjc_page(0); }

/* 603 行（同函数，稍后）—— 无条件推 .val */
tjc_set_val(OBJ_CONC, (int)(g_ppm));      // 预热期推的就是 0

/* 496~504 行 hmi_update_init_cover() —— "显示 --" 的唯一实现 */
if (g_warm) {
    ...
    tjc_set_txt(OBJ_CONC, "--");           // ★ 对数字控件推 .txt：被屏端忽略
} else { ... }
```

### 3.2 代码自己的注释就是答案（`main.c` 600~602 行）

```c
/* 主页: 浓度显示固定 ppm (v2 已移除单位切换)
   cc 为数值组件(type 54, 只有 .val, 无 txt 属性; 已与 cct 合并)。
   必须推 .val 而非 .txt(推 .txt 被忽略 -> 屏幕恒显示初始 0) */
```

→ 同一份文件里，603 行按这条规则推 `.val`，而 `hmi_update_init_cover()` 却还在推 `.txt` —— **自相矛盾**，被忽略的是后者。

### 3.3 屏端 `C4F7N_v7b.HMI`（实测）

| 证据 | 值 |
|---|---|
| `主页/cc` 类型 | **54（数字控件）** |
| `cc.val`（页面存储值） | **0** |
| `cc.txt` | `""` |
| `cc` 的 codesload / codesup / codestimer | **全 0 行**（无任何屏端脚本参与） |

→ `cc` 显示什么**完全由固件最后推的 `.val` 决定**，页面跳转后显示的是存储值/最近推送值。

### 3.4 跳过链路本身是通的

`v7b` 初始化页块内 `printh 07` 恰好 1 处（挂在 `lg_i` 隐藏按钮的触摸事件，脚本记录 `att-39`）；
固件 `hmi_on_init_skip()`（739 行）置 `g_skip=1`（有 `SKIP_ARM_MS=5000u` 开机 5s 静默窗，740 行），
`app_refresh` 531 行收到后 `tjc_page(0)` —— 均正常。

## 4. 为什么以前没发现

| 时间 | 事件 |
|---|---|
| 09-18 | 真机验证"预热期显示 `--`"通过 —— **当时 `--` 由独立文本覆盖层 `cct` 显示**（文本控件，推 `.txt` 有效） |
| 09-22 | 决策**移除 `cct` 覆盖层**（`main.c` 495 行注释：「不再叠加 cct 覆盖层, 避免遮挡: 直接用主浓度组件 cc 显示 "--"」），把 `--` 的责任交给 `cc.txt` —— **从这一刻起 `--` 再也显示不出来**，但因为屏幕锁在初始化页（页3）、`cc` 在主页看不见，无人察觉 |
| 09-24 | 真机联调：点跳过 → 进主页 → `cc` 第一次可见 → 暴露 |

**附带发现（同一根因）**：即使**不点跳过**、等 60s 自然结束，`--` 同样不会出现 —— `g_warm=0` 后 603 行直接开始推数值（无帧时 `sensor_read_ppm()` 返回 0），`--` 被跳过。`hmi_update_init_cover()` 目前整体是**死代码**。

## 5. 修复方向（暂不实施，供决策；约束 = 不新增控件）

| 方案 | 改动 | 评价 |
|---|---|---|
| ~~A~~ | ~~主页加回文本覆盖控件（原 `cct`）~~ | ❌ **否决**（2026-09-24 用户裁定：**不新增控件**——遮挡 / 显示不稳定风险，当年移除 `cct` 正是为此） |
| B | 固件 603 行加 `if (!g_warm)` 门控不推 `.val` | ❌ **单独不可行**：数字控件存不了 `--`，只会停在页面存储值（出厂 0），仍显示 0 |
| **C（推荐）** | **复用 `cc` 本身：数字控件（type 54）改为文本控件（type 116）**，固件 603 行改推 `.txt` 字符串：预热期 / 无有效帧时推 `--`，正常推格式化数值；`hmi_update_init_cover()` 保留（它推的 `--` 对文本控件终于生效） | ✅ **不新增控件**；文本控件推 `.txt` 是常规操作；报警变色 `tjc_set_pco(cc,…)` 不受影响。<br>代价：① 需在编辑器把 `cc` 类型改文本（同位置/尺寸/字体 font=9）；② 数值格式化移交固件 `snprintf`（格式需先确认，见下）；③ 需设 `txt_maxl` ≥7（容纳 `1500.0` / `--`） |
| D（备选） | 预热期推 `cc.vis=0` **隐藏数字控件** + 复用现有单位控件 `pu`：推 `pu.txt="--"`，预热结束恢复 `"ppm"` | ✅ 不新增控件、无遮挡。<br>代价：① 需新增 `tjc_set_vis()` 帮助函数（现只有 val/txt/pco/var）；② `--` 出现在**单位位置**而非浓度位置，语义稍弱；③ 恢复顺序需保证 `cc.vis=1` 与 `pu.txt="ppm"` 同周期完成，避免中间态 |

**待确认点（C 落地前）**：`cc` 当前 `vvs`（小数位）未能从屏包解出（属性键名非 `vvs`）——
固件现在推 `(int)g_ppm`；**真机看一眼当前显示格式**即可定（12 ppm 显示 `12` → vvs=0；显示 `0.12` → vvs=2，
后者意味着现有推值方式本身还有缩放错误）。改文本控件后固件按同格式 `snprintf` 即可。

**顺带要定的语义**（与修复一起决策）：
1. **跳过 ≠ 提前结束预热**：现在点跳过只切页，`g_warm` 仍为 1 到 60s —— 不报警、不记历史（587 行 `!g_warm` 门控）、`g_ppm` 强制 0 都继续生效。这是否符合预期？
2. **预热结束后、第一帧有效数据前**要不要也显示 `--`？Sensor 层有现成的 `g_warmup` 标志（收到首帧前置位，`sensor.c` 18/77 行）可用于判断。

## 6. 结论

- 根因：**预热 `--` 的显示载体（`cc.txt`）对数字控件无效**，09-22 移除文本覆盖层 `cct` 时引入，被初始化页锁页掩盖至今。
- 影响面：仅显示问题——预热期浓度强制 0、不报警、历史不记录的逻辑**不受影响**（均按 `g_warm` 正常门控）。
- 状态：**未实施修复**，待决策（方案 A 推荐）。
