## 一、问题与证据

### 实测数据点（2026-10-08）

万用表测得电池 **13.76V** 时，屏上显示 **42%**。

### 固件换算是线性的

`battery.c:106`：
```c
pct = (int)((v - BAT_EMPTY_V) / (BAT_FULL_V - BAT_EMPTY_V) * 100.0f);
/* = (13.76 - 12.0) / (16.3 - 12.0) × 100 = 40.9%  ← 与实测 42% 吻合 */
```

### 但锂电池放电曲线不是直线

| 真实容量 | 真实组压（4S，含负载压降） | 固件线性显示 | **偏差** |
|---|---|---|---|
| 80% | ≈ 15.6V | 84% | +4 |
| 50% | ≈ 15.0V | 70% | **+20** |
| 30% | ≈ 14.5V | 58% | **+28** |
| **15%（本次实测点）** | **13.76V** | **42%** | **+27** |
| 10% | ≈ 13.5V | 35% | +25 |
| 5% | ≈ 13.2V | 28% | +23 |
| 0% | ≈ 12.6V | 0% | 0 |

**根因**：一条直线穿过"缓降→陡降"的放电曲线，中下段必然虚高。

### 它解释了此前的故障

"显示 30% 就关机" ⇒ 固件算 13.29V ⇒ **真实只剩 5~8%** ⇒ 静默状态下屏那 0.17A 负载就足以把电压推到 PCM 保护阈值以下 ⇒ **电池真没电了，不是死机**。

## 三、曲线初值（通用 4S 18650 / 4S3P，仅供起步）

```c
typedef struct { float v; uint8_t pct; } bat_curve_point_t;

/* ⚠️ 与电池型号 + 负载强相关；换电池后必须按 §6 重新标定！
 * ⚠️ 宁可低估（提前告警）也不要高估（用户以为还有电却被关机）。
 *   下列数据取"含间歇泵负载"的偏保守值。 */
static const bat_curve_point_t BAT_CURVE[] = {
    {16.60f, 100}, {16.00f,  90}, {15.60f,  80}, {15.20f,  66},
    {14.80f,  50}, {14.50f,  38}, {14.10f,  25}, {13.80f,  15},
    {13.50f,   8}, {13.20f,   4}, {12.60f,   0},
};
#define BAT_CURVE_N  (sizeof(BAT_CURVE) / sizeof(BAT_CURVE[0]))
```

**查表函数**：

```c
static uint8_t battery_v_to_pct(float v) {
    if (v >= BAT_CURVE[0].v) return BAT_CURVE[0].pct;
    if (v <= BAT_CURVE[BAT_CURVE_N - 1].v) return 0;
    for (uint16_t i = 1; i < BAT_CURVE_N; i++) {
        if (v >= BAT_CURVE[i].v) {
            const float dv = BAT_CURVE[i].v - BAT_CURVE[i - 1].v;
            const float dp = (float)(BAT_CURVE[i].pct - BAT_CURVE[i - 1].pct);
            return BAT_CURVE[i - 1].pct + (uint8_t)((v - BAT_CURVE[i - 1].v) / dv * dp);
        }
    }
    return 0;
}
```

## 五、⚠️ 曲线与负载的关系（必须标定的根本原因）

同一块电池，**负载越大，端电压越低，曲线整体下移**：

| 负载 | 典型电流（电池侧） | 同一 SOC 的端电压 |
|---|---|---|
| 仅屏幕（静默） | ≈ 0.17A | 偏高（曲线左上） |
| 屏 + 传感器 | ≈ 0.3A | 中 |
| 屏 + 传感器 + 泵 | **≈ 0.9A** | 偏低（曲线右下） |

⚠️ **若用"静默低负载"曲线，用户在实际使用（开泵）时会再次被"突然关机"** —— 因为查表给出的百分比偏高。

**取舍原则：宁可低估，不可高估**（低估 = 提前告警，用户多充一次电；高估 = 到点突然关机，产品被判定"质量差"）。

⇒ **标定必须用"含泵的典型使用"负载**，不能用静置状态标。

## 六、★ 换电池后的重新标定流程（必须执行）

⚠️ **本文档的表是按当前这块电池（已到寿命末期）估的，换新电池后必须重做。**

### 6.1 标定前的准备

1. **满电静置 2 小时**（消除充电后的电压回弹）
2. 量电池端子电压 → `V_100`（这就是 100% 点；注意 SS34 压降，满充约 **16.3~16.4V** 而非 16.8V）
3. 准备一张记录表：**每 5 分钟记一行（时间 / 电压 / 负载状态）**

### 6.2 采样

| 阶段 | 做法 |
|---|---|
| 放电 | 按**正常使用**（开屏 + 传感器 + **周期性开泵**）放电 |
| 记录 | 每 5 分钟量一次电池端子电压，**静置读数优先**（负载瞬间波动大） |
| 终止 | 到"无法开机"（PCM 切断）为止 |
| 中断 | 若中途关机，立刻记下**关机前的电压**，那是 0% 点 |

### 6.3 换算成容量轴

⚠️ 只靠万用表无法直接读 SOC，用**时间 + 估算平均电流**：

1. 从满电到关机记录总时长 `T`（小时）
2. 估算平均电流 `I_avg`（A）：用万用表在 10A 档**串在电池回路**量一次开机瞬间的稳态电流；若不方便，按功耗预算估算 ≈ **0.5A**
3. 累计容量 `Q = I_avg × T`（Ah）
4. 每个采样点的 SOC = `(1 − Q(t)/Q_total) × 100%`

> 精度说明：±15% 以内（受 `I_avg` 估算误差影响）。**对"要不要提前充电"这个用途足够。**

### 6.4 生成曲线表

把各点 `(电压, SOC%)` 排序，**取 8~12 个点**填入 `BAT_CURVE[]`（电压必须**降序**、SOC 必须**递减**）。

### 6.5 校验（至少 3 点）

| 校验点 | 判据 |
|---|---|
| 满电静置 | 显示 **100%**（±2%） |
| 放电至一半时长 | 显示 **50% ± 8%** |
| 关机前 10 分钟 | 显示 **≤ 10%**（宁可低） |

### 6.6 同步文档

标定完成后，把**实测数据表**追加到本文件 §6.7，并更新 `MEMORY.md` 的电量基线数字。

## 八、局限与后续

**本次修正解决**：显示虚高、告警时机不对、"突然关机"被误判为死机。
**本次修正不解决**：电池衰减本身、PCM 物理切断（**换电池才是根治**）。

若后续追求准确 SOC，应改用**库仑计芯片**（MAX17205 / BQ34Z100，走 I²C 读剩余容量与健康度）—— 属路线图 R4「传感器寿命/工时累计」的延伸。

### 8.1 ✅ 已解决：低电三级阈值与新曲线不匹配（v47，2026-10-08）

#### 未被本项解决的

⚠️ **"6% 时关机无法启动"不是软件问题** —— 是**电池衰减到寿命末期 + PCM 物理切断**（实测电池端子 0.003V / 插充电器恢复 14V）。任何软件都拦不住，**根治是换电池**。

本项改的是**让告警在正确时点出现**：以前用户看到 35% 才收到"请充电"提示（实际早已没电），现在 **20% 就提醒**，留出 10% 的缓冲时间去充电。
