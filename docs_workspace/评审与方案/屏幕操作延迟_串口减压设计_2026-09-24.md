# 设计：操作屏幕延迟的根因与串口减压方案

> 2026-09-24 排查 + 设计。**只设计，未实施。**
> 现象：真机上操作屏幕（按键/翻页/滑块）有明显延迟。

## 1. 结论（TL;DR）

**是，需要减轻串口压力 —— 但只减压不够，要三层一起看：**

| 层 | 手段 | 收益 | 风险 |
|---|---|---|---|
| **L1 减量**（纯固件） | 脏标记 + 只在历史页刷表 + 行级增量 | TX 占用 **~330% → <10%**，主循环 0.84~2.66s → **0.25~0.35s** | 低（业务逻辑不变，只少发） |
| **L2 非阻塞**（结构性） | TX 环形队列 + 中断/DMA，`tjc_set_*` 只入队 | 主循环彻底不被发送卡住；触摸响应 ≈ ms 级 | 中（改 tjc_cmd.c 发送层，业务 API 不变） |
| **L3 提速**（硬件配合） | USART3 9600 → **115200**（屏+固件同批） | 带宽 ×12，任何残余流量都不再是问题 | 中（**屏与固件必须同批升级**，波特率不匹配会互听不懂） |

**推荐顺序：L1 → L2 →（可选）L3。** 只做 L1 延迟就能从 0.8~2.7s 降到 ~0.3s；L1+L2 后"即点即响"；L3 是锦上添花，可与下次烧屏窗口合并。

## 2. 根因：串口 TX 超载 3.3×，主循环被发送吃满

### 2.1 带宽账本（实测口径，9600 8N1 = 960 B/s）

| 流量源 | 频率 | 字节 | 折算 TX 时间 |
|---|---|---|---|
| `app_refresh()`（250ms 名义周期） | 每轮 | **567 B**（main.c 475 行注释自证） | **0.59 s** |
| `refill_table()`（历史表 24 行×3 列 + 页码 + 统计） | 每 2 s | **~1749 B** | **1.82 s** |
| **合计** | 每 ~2.66 s | ~6285 B | **~6.5 s** |

→ **2 秒的墙钟时间要发 6.5 秒的数据：TX 超载 3.3×。** 主循环永远在等串口。

### 2.2 为什么表现为"操作延迟"

- 触摸链路本身是快的：`USART3_IRQHandler`（优先级 0）→ `HAL_UART_RxCpltCallback` → `hmi_get_feed()` 逐字节 → `hmi_on_rx_byte()` → `hmi_callback` **只置标志**（`g_skip`/`g_cal_req`/`g_thr_dirty`…）——**中断里即时完成**。
- 但标志的**消费在主循环**：`while(1)` 每轮才执行 `app_apply_threshold` / `cal_poll` / 页面切换（531 行 `tjc_page(0)`）等动作。
- 主循环每轮被阻塞发送卡住：常规轮 0.59 s（TX）+ 0.25 s（HAL_Delay）≈ **0.84 s**；含 refill 的轮 ≈ **2.66 s**。
- → **触摸到响应的延迟 = 最多一整轮（0.84~2.66 s），平均 0.4~1.3 s。** 与真机感受一致。
- 另：屏端也在被持续灌指令（约 70% 线路利用率 + refill 尖峰），TJC 自身的指令解析与触摸渲染互相竞争，再加一层屏侧延迟。

### 2.3 流量为什么这么大：三类浪费

1. **无条件重发不变量**：`app_refresh` 每轮都发"探头 已连接"/"泵 未启动"（~24 B×2）、最大/最小值文案（~30 B×2）、统计 5 项（~90 B）、静音按钮、色条/圆点、电量 **3 个页的 chip 各发一遍**——这些绝大多数轮次根本没变。
2. **refill_table 不看页面**：不管停在主页还是历史页，每 2 s 全量刷 24 行×3 列（~1749 B）。注释自证当年因"进页事件触发 refill 历史页恒空"而改成无条件。
3. **9600 bps 底子太薄**：960 B/s，任何一层浪费都被放大 12 倍。

## 3. L1 减量（纯固件，先做）

### 3.1 脏标记：值不变不发

- 为周期性更新的对象建**上次发送值缓存**（数值直接比，字符串比内容），变化才 `tjc_set_*`。
- 覆盖：探头/泵状态（609-611）、cma/cmn（617-618）、统计 5 项（640-656）、静音按钮（578）、色条/圆点（626-628）、电量。
- 电量 `tjc_set_bat()` 现在固定 3 连发（3 个页的 chip）→ 改为**只发当前页那个** + 百分比变化才发。

### 3.2 页面感知：`g_cur_page`

- 固件**已经知道当前页**：① 自己调 `tjc_page()` 处（上电锁页、跳过切主页）；② 屏幕导航按钮 `printh 4N` → `hmi_on_page_enter(p)`（hmi_callback.c 35 行）。
- 新增 `g_cur_page`，两处同步赋值 → 供 refill/电量/后续扩展做页面门控。

### 3.3 refill_table 门控 + 增量 + 放宽

- **仅 `g_cur_page == 历史页` 时执行**；进入历史页事件后延时 ~100ms 先补一次（规避切页瞬间，当年"进页触发恒空"的坑用这条绕开，需真机复验翻页/新记录）。
- 常驻刷新 2 s → **5 s**（新记录本身受 `HIST_PERIOD_MS` 节流，不存在丢新行）。
- **行级增量**：缓存上一轮 24 行的内容，只重发变化的行（通常只有最新一行的时间/浓度/序号）。

### 3.4 预期

| 指标 | 现状 | L1 后 |
|---|---|---|
| 主页每轮 TX | 567 B / 0.59 s | **~60-120 B / 0.1 s**（只有 cc 数值变化、秒、偶发电量） |
| 历史页每 2 s | 567×8 + 1749 = 6285 B | ~1500 B（仅 refill，且行级增量后更低） |
| 主循环单轮 | 0.84 ~ 2.66 s | **0.25 ~ 0.35 s** |
| 触摸响应延迟 | 0.4 ~ 1.3 s（平均） | **≤ 0.35 s** |

## 4. L2 非阻塞发送（结构性根治）

- `tjc_send_raw()`（tjc_cmd.c 17-26 行，现为 `HAL_UART_Transmit` 阻塞）改为：**写入 TX 环形队列 → 使能 USART3 TX 中断（或 DMA）**；发送完成中断从队列取下一片。
- `tjc_set_*` 全部 API 签名不变（业务层零改动），只是从"阻塞到发完"变成"入队即返回"。
- **队列满策略**：周期刷新类可丢（置脏标记，下轮重发）；**命令类不可丢**（页面切换 / 阈值 / 标定 / 报警开关）→ FIFO 保底 + 忙等上限。
- 收益：主循环不再被任何发送卡住 → 触摸响应 = 一次循环（ms 级）；即使偶发大流量（进历史页首次全量 refill）也不冻结交互。
- 注意点：① `HAL_UART_Transmit` 移除后 `tjc_page()` 等的**顺序仍由 FIFO 保证**；② 与 RX 回调共存（不同向量，无冲突）；③ 喂狗节奏不受影响。

## 5. L3 提波特率（可选，与烧屏窗口配合）

- USART3 9600 → **115200**：屏端在编辑器/`.tft` 里持久化 `bauds=115200`，固件 `usart.c` 73 行同步改。
- ⚠️ **屏与固件必须同批升级**：波特率不匹配则互相听不懂。升级顺序写进烧录文档。
- 可选兼容（需真机验证）：固件上电先以 9600 发 `bauds=115200` 再自切 —— 旧屏也能用；若屏已是 115200，收到的 9600 码流是乱码，TJC 会忽略无效指令，固件随即自切 → 收敛。**列为可选项，不作为默认**。
- STM32F103 @72MHz 跑 115200 无压力；传感器在 UART4（独立外设），不受影响。

## 6. 验收指标（实施前先定）

| 指标 | 目标 | 测法 |
|---|---|---|
| 触摸→固件动作 | ≤ 1 个主循环（目标 ≤ 100 ms） | 串口抓包：屏 `printh` 到固件第一条应答的间隔 |
| 主循环单轮耗时 | 主页 ≤ 50 ms；历史页 ≤ 200 ms | GPIO 翻转 + 示波器，或 tick 差值打点 |
| 串口线路利用率 | ≤ 30% | 抓包统计字节数 |
| 回归 | T-05 标定、T-06 回推、历史翻页/新记录、按键音不丢 | 真机清单复跑 |

## 7. 实施顺序与风险

| 顺序 | 内容 | 为什么 |
|---|---|---|
| 1 | **L1 减量**（脏标记 + g_cur_page + refill 门控/增量） | 收益最大、纯固件、不动发送机制，风险最低 |
| 2 | 真机复测延迟与回归清单 | 若已达标（≤0.35s）可先停 |
| 3 | **L2 非阻塞** | 结构性保险；API 不变，改动集中在 tjc_cmd.c |
| 4 | **L3 115200** | 与下次烧屏窗口合并做，升级顺序先写进文档 |

**明确不建议**：只做 L3 不做 L1 —— 带宽宽了但"每轮无条件重发不变量"的浪费仍在，屏端解析负担、未来功能扩展的余量都被白白吃掉。
