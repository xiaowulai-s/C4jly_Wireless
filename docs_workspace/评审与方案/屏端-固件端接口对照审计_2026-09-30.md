## 一、P1 清单

### P1-1 ★ 报警色条 `dvr` 只推主页，其余 3 页永不更新

`main.c:717` 是硬编码对象名：

```c
if (full || stc != s_stc) { s_stc = stc; tjc_set_pco(OBJ_STRIP, stc); }   /* OBJ_STRIP = "dvr" */
```

它**没有走 `sfx` 机制**（同文件的圆点/探头/泵都走 `snprintf("pcXd%s", sfx)`），而屏端有 4 份色条副本、且**初始色各不相同**：

| 对象 | 页 | type | 初始 pco | 固件是否推送 |
|---|---|---|---|---|
| `dvr` | 4 主页 | 116 | **0** | ✅ 推（吃 `full`） |
| `dvr_s1` | 5 设置 | 116 | **57149** | ❌ 从不 |
| `dvr_s2` | 0 历史 | 116 | **57149** | ❌ 从不 |
| `dvr_i` | 6 初始化 | 116 | **0** | ❌ 从不 |

**影响**：主页顶栏色条随报警变色（绿/橙/红），切到设置页/历史页/初始化页时色条**永远停在编辑器里设的静态色**（且与主页不同色）→ 跨页视觉不一致；若用户靠色条判断报警状态，在非主页页会误判。

**建议**（二选一，需先确认设计意图）：
- (a) 若各页色条**应同步报警色** → 把 717 行改成与圆点同样的 `snprintf("dvr%s", sfx)`（一处改动，顺带修正历史页/设置页/初始化页）
- (b) 若其它页色条**本就是静态装饰** → 至少把 `dvr_s1/s2/i` 的初始 `pco` 统一成与主页正常态一致，并在协议头注明"仅主页色条有语义"

### P1-2 ★ 固件版本行写死 `V1.0.0`

设置页 `fw`（type 116）初始文本 = **"固件版本    V1.0.0"**，固件**从不推送**该对象（`protocol.h` 无对应宏，全码检索无引用）。

**影响**：实际运行的是 v39 固件，屏上却恒显示 `V1.0.0` —— 现场/售后依据屏显版本会误判。

**建议**：加 `OBJ_FW_VER "fw"` 宏 + 上电推一次真实版本串（编译期常量即可），或在屏端把该行改成不带版本号的产品说明。

### P1-3 ★ 产品编号写死 `SN-C4F7N-260`

设置页 `sn`（type 116）初始文本 = "产品编号    **SN-C4F7N-260001**"（`txt_maxl=28`），固件从不推送。

**影响**：所有机器显示同一编号；屏幕上给了一个"看起来像真序列号"的值，容易被当成真编号记录/追溯。

**建议**：这条与路线图 **R6（SN 页）** 重合 —— 要么尽快实现"逐机唯一 SN"，要么把屏端文案改成明确的占位（如 `SN-待写入`），避免误用。

### P1-4 命令码 `0x18 (PUMP_TOG)` 无屏端发射源 → 整条链路是死代码

| 命令码 | 屏端是否发送 | 固件实现 | 结论 |
|---|---|---|---|
| `0x18 HMI_CMD_PUMP_TOG` | ❌ **无任何 `printh 18`** | `hmi_callback.c:25 → hmi_on_pump_toggle()` | **死路径** |
| `0x24 HMI_CMD_TEST_TOGGLE` | ✅ `4.pa/ptg` | `hmi_callback.c:28 → hmi_on_test_toggle()` | 有效路径 |

而两者实现不同：`main.c:868 hmi_on_pump_toggle()` 只 `pump_toggle()`；`main.c:1109 hmi_on_test_toggle()` 置 `g_test` 并 `pump_set(g_test)`。屏端"泵/测试"按钮走的是后者。

**影响**：① `hmi_on_pump_toggle()` / `pump_toggle()` 成为**无人调用的死代码**；② 契约注释（`protocol.h:31` 把 `0x18` 描述为"屏幕『开始测试/停止测试』按钮"）与实现**不符** —— 实际那个按钮发的是 `0x24`。以后若有人想"单独控制泵"，按注释去用 `0x18` 会发现屏端根本没有入口。

**建议**：删除 `0x18` + `hmi_on_pump_toggle`/`pump_toggle`（或反之，明确保留并补屏端按钮），并修正 `protocol.h` 的注释。

### P1-5 协议头头部注释与实际严重不符（会直接导致接错线）

`c4f7n_hmi_protocol.h:4-5`：

```
 * 版本: v2 (命令码)  配套屏幕工程: C4F7N_HMI_v18.HMI
 * 串口: USART1 PA9(TX)/PA10(RX) @ 115200 8N1, 无流控
```

实测三项皆错：

| 注释 | 实际 |
|---|---|
| `USART1 PA9/PA10` | **`USART3` PB10/PB11**（`usart.c`，手工配置；USART1 是预留） |
| 配套 `C4F7N_HMI_v18.HMI` | 当前 `C4F7N_v8.HMI`（新命名轨，旧轨已废弃） |
| 版本 `v2` | 命令码表本身没变，但对象集已随 v34~v39 大幅演进 |

**建议**：立即修正（这是"新人接手第一眼会看到"的地方）。

## 二、P2 清单（卫生 / 隐性风险）

### P2-1 21 个 `OBJ_*` 宏"定义了但从不被引用"，与实际实现脱节

审计结果：`OBJ_PROBE_CHIP("pc0")`、`OBJ_PUMP_CHIP("pc1")`、`OBJ_DOT_PROBE/…_P1/_P2("pc0d"/"pc0d_s1"/"pc0d_s2")`、`OBJ_DOT_BAT(_P1/_P2)`、`OBJ_*_I` 系列（`pc0_i`/`pc1_i`/`pc0d_i`/`pc1d_i`/`pc2d_i`）、`OBJ_TBL_HEAD_T/P/SN("ht"/"hc"/"hsnL")` —— **全部 0 次引用**。

原因：这些名字实际由**动态拼接**产生（`main.c:470-476`）：

```c
snprintf(n, sizeof(n), "pc0d%s", sfx); tjc_pic(...);   /* sfx ∈ {"", "_s1", "_s2", "_i"} */
```

**风险**：后人看到宏名以为那才是"官方入口"，改名/新增页时按宏名去改，**改了不生效**（真名是拼出来的）。`OBJ_TBL_HEAD_*` 更彻底 —— 屏端表头是静态文本，根本不需要 MCU 更新。

**建议**：把 `_P1/_P2/_I` 这类"拼接用基名"统一注释为**基名模板**（不是完整对象名），或直接删除未使用宏。

### P2-2 重复定义：`OBJ_HOME_PROBE`/`OBJ_HOME_PUMP` 与 `OBJ_PROBE_CHIP`/`OBJ_PUMP_CHIP`

`protocol.h:69-70` 与 `:124-125` 定义了同值的两组宏（都是 `pc0`/`pc1`），且两组都无引用。

**建议**：删掉其中一组。

### P2-3 陈旧宏 `OBJ_TBL_PANEL = "p2D"`：屏端不存在该对象

屏端历史页的实际对象是 `p2L` / `p2R`（左右两列面板），**没有 `p2D`**；且该宏引用 0 次。

**建议**：删除（属于 v2 改版残留）。

### P2-4 `OBJ_LOWBATT` 宏注释被复制污染

`protocol.h:89` 一行里挂了**两段注释**，第二段（"初始化页 自检结果行(T-15)…"）是从 `OBJ_SELFTEST_I` 复制过来的，与 `lb` 无关；`HMI_AUDIO_ID`(:121) 与 `HMI_AUDIO_LOWBATT`(:122) 也有同样的重复粘贴。

**建议**：清理。

### P2-5 `hmi_get.c:77` 注释引用了**不存在的宏** `OBJ_THR_HI_VAL_APPLIED`

该标识符在协议头里**没有定义**，只在 `hmi_get.c` 的块注释中出现（全码唯一出现处）。后人照抄会编译失败。

**✅ 已修（v45）**：注释里的宏名改为真实存在的 `OBJ_THR_HI_VAL`（=`"h"`）—— `thr_hi_readback_poll()` 用的正是它。

### P2-6 设置页 `load` 里的 `if(h.val!=500)` 恒为假（哨兵值脆弱）

`5.pa` 的 `load` 脚本：

```
if(h.val!=500)
{
thr=h.val
}
h.val=thr
```

`main.c:243-245` 的注释说明了机制（进页按页面初值绘制 → 必须由页面从全局 `thr` 刷新）。

> ⚠️ **2026-09-30 复核：原判「恒为假」可能不成立，已降级为「待实测」。**
> 实测属性发现 **`h` 是 type54 且 `vscope=1`（全局作用域）** —— TJC 全局控件**切页时值会保留**，`h.val` 并不必然回到页面初值 500 ⇒ 该 `if` **可能真会执行**（属"屏端 h 被改但固件尚未收到"的容错）。
> **实测方法**：阈值改到非 500 → 退出设置页 → 再进，看 `h` 是否仍显示该值。保留 ⇒ 有效容错（不动）；回 500 ⇒ 确为冗余（再删）。
> 用户裁定：**本轮跳过，实测后再定**。

**建议（若实测证实冗余）**：删掉 `if` 分支只留 `h.val=thr`；或保留但把哨兵 500 换成具名常量并加注释。

### P2-7 `set_txt(OBJ_CONC)` 对 type 54 控件无效（已知）

`main.c:569`（v45 前）用 `.txt` 推 `cc`（type 54 数字控件）→ 屏端静默忽略。预热期主页实际显示的是 `cc.val=g_ppm`（=0）。

### P2-8 `set_txt("ptg")` 用字面量而非宏

`main.c:677`（v45 前）直接写 `"ptg"`；`OBJ_*` 体系里没有它的宏。
**✅ 已修（v45）**：新增 `OBJ_TEST_BTN "ptg"`（`protocol.h`）并替换字面量，注释标注"**屏端 `txt_maxl=8B`，恰容 4 汉字（`开始测试`），改文案须同步改 maxl**"。

### P2-9 `SIM_MODE` 条件编译块残留

涉及 **4 处**：`main.c:589-591`（`g_test=1` 强制测试中）· `main.c:607-611`（跳过 60s 遮罩）· `sensor.c:112-155`（假数据正弦实现）· `sensor.h:22`（开关，注释态）。当前**未启用**（工程 Define 只有 `USE_HAL_DRIVER,STM32F103xE`）→ 无害。但若误开，**"测试"将无法停止**（每轮被强制置 1）。

### N1 ✅ **经确认 = 设计口径，非缺陷**（2026-09-30 用户裁定；原报告结论作废）

### N3 `OBJ_STRIP` 死宏 —— 用途说明 + 一处**注释错误**

**对象/功能**：`dvr`（type 116，x=0 **y=64** w=1024 **h=2**，`txt=" "`）= **页面顶栏的报警等级色带**（标题区下方一条 2px 细线，全宽贯穿）。⚠️ 其可见色**靠 `bco`（控件背景色）填充**，**不是 `pco`**（详见下方"延伸疑点"）。
4 页各一份副本：`dvr`(主页) / `dvr_s1`(设置) / `dvr_s2`(历史) / `dvr_i`(初始化)。
颜色档位（`protocol.h:140-146`）：**橙 `62689`=1 级报警 · 红 `59944`=2 级报警 · 深灰蓝 `12777`=正常态**（v43 起正常态用屏端原色）；同一组常量也被 `CONC_COLOR[4]`（`main.c:157`，v43 前名为 `ALARM_COLOR`）用于浓度大字配色。
**设计作用**：让用户在**任意页面**都能一眼看到当前报警状态。⚠️ **实际直到 v42 才真正生效** —— 此前一直推 `pco`（对空格无效），4 页**都**改不动。

**宏为何成死宏**：v40 把推送改为 `snprintf(n, sizeof(n), "dvr%s", sfx); tjc_set_pco(n, stc);`（`main.c:480`；**v42 起为 `tjc_set_bco`**）——宏只能表达主页那一份、表达不了按页后缀 → `OBJ_STRIP` 自此 **0 引用**。

**★ 顺带查出**：`protocol.h:51` 的注释写的是 **"电量色条 pco"** —— **错**，它是**报警色条**（"电量"另有 `pc2d*` 圆点那一套）。错误注释 + 英文残留 `/* use existing obj */` 正是"后人误判"的源头。
**建议**：删除该宏，或改写为 `/* 报警色条基名: 按 sfx 拼页后缀 dvr/dvr_s1/dvr_s2/dvr_i, 见 main.c hmi_update_status_chips() */`。

**✅ 已修（v44）**：注释已按此改写，并补上关键警示"可见色靠 `bco` 填充、**必须用 `tjc_set_bco`**，推 `pco` 对空格无效"；宏**保留**作为基名锚点（不再叫"电量色条"）。

**★ 延伸疑点 —— 已获真机证实（2026-09-30 用户答复"颜色不变"）**

`dvr` 的 `txt` 是**单个空格（无笔画）**，而 TJC 文本控件的 **`pco` = 文字前景色** ⇒ **空格无从着色，推 `pco` 在真机上无任何可见效果**；那条 2px 线实际是 **`bco`（12777）的固定装饰线**。

⇒ **P1-1 结论修正：真根因不是"只推主页"，而是"属性用错"** —— 原实现 4 页**都**改不动（v40 的按页 `pco` 推送同样无效）。

**修法候选**（成本从低到高）：

- **A. 固件改推 `bco`** —— 新增 `tjc_set_bco` + `HMI_CMD_SET_BCO` 宏，`main.c:480` 改一行，**屏端零改动**。风险 = `dvr` 的 `aph=127`（透明度）是否影响 `bco` 可见性 → 需真机复验。
- **B. 屏端 `dvr` 换图片控件（type 112）+ 3 张 1024×2 色条图，固件 `tjc_pic("dvr"+sfx, 图号)`** —— 与已验证有效的 `pc2d` 电量圆点**同法，最可靠**。代价 = 屏端加 3 个图片资源 + 改 4 页控件。
- ~~C. 屏端给 `dvr` 填字符改 `pco`~~ —— **不可行**（单字符仅约 8px 宽，`w=1024` 填不满），已排除。

**★ 教训（流程）**：v40 真机验证时用户只回报了"固件版本行"一项，当时却按"P1 五条全过"记档 → **验证清单必须逐项确认，不得由单项通过推定其余通过**。
