## 2. 必读硬约束（违反会造成不可逆损伤）

### 2.1 编码

- 含中文的 **C 源文件必须 GBK(ANSI 936)**。禁止用会输出 UTF-8 的工具（Write/Edit）直接改写；正确做法是「写 UTF-8 临时脚本 → 以 UTF-8 读入 → **以 GBK 写出**」。
- PowerShell 读写必须 `[System.Text.Encoding]::GetEncoding(936)`；**PS 5.1 的 `-Encoding gbk` 无效**。
- **乱码扫描必须双线索**：`EF BF BD` 字节数 **和** `U+FFFD` 计数。`EF BF BD` 在 GBK 下是合法汉字（`锟斤拷`），只查 `U+FFFD` 会漏检。
- 编码二次毒化**不可逆**，原文丢失后只能语义重建。
- `.md` 文档为 UTF-8，不受此约束。

### 2.3 屏端 `.HMI` 修改（唯一合规链路）

`.HMI` 是私有容器，页块带**内容校验戳**（CRC32 ^ 长度常量），**手工改二进制会被 Editor 判为 Version mismatch / Loading Page Failed**；容器目录校验和算法未破解。因此只能：

```powershell
cd d:\Demo\C4jly\tjc-hmi-toolkit

# 1) 提取页面块
.\tools\extract-pas.exe .\C4F7N\C4F7N_v4.HMI .\C4F7N\_v4fix

# 2) 用 lib/page.js 做 parse → 改属性 → build 写回（必须做 roundtrip 字节级校验）

# 3) 回打包：模板 = 当前在用的 .HMI，资源目录 = 上一步目录
.\tools\hmipack-tjc.exe .\C4F7N\C4F7N_v4.HMI .\C4F7N\_v4fix .\C4F7N\<新文件>.HMI
#    成功标志：末尾 "RESULT: opens, N resources"，且每页 "stamp ... check=33 ok"

# 4) 引擎级全页验证
.\tools\verify_all_pages.exe .\C4F7N\<新文件>.HMI      # 期望 pages ok=6 bad=0
```

- ⚠️ **模板必须用当前在用的 `.HMI`**（本次实测：用 `C4F7N_v4.HMI` 作模板成功）。旧文档建议的 `base.HMI` 是 4 页空白容器，**用它打包会得到错误工程**（这正是 `C4F7N_v5.HMI` 报「索引超出数组界限 + 宽高问题」的原因之一）。
- ⚠️ 打包前**结束 USART HMI / Keil 进程**（会锁文件）。
- ⚠️ 改后**不要动既有对象的属性字节宽度**；新增控件必须同步重算 `endx = x+w-1`、`endy = y+h-1`。
- ⚠️ `verify_all_pages` **只验结构**，不验脚本行格式；脚本类问题只能靠 USART HMI GUI 打开编译发现。

### 2.4 屏端脚本（TJC 方言）

- 单行 **≤15 字节（GBK）**；≥16 会被当 attr 解析 → 引擎崩溃「索引超出数组界限」。
- `obj.txt=` 文本必须 **GBK**；`txt` 不可为空串，空写 `" "`。
- **不支持 `else` / `endif`**；`if(cond)` 必须接 `{}`。
- 不支持 `print` / `cls` / `obj.bco=` 赋值；复合赋值 `+=`/`-=` 需展开。
- 按钮 `val` 是**按下状态标志**，不能存业务状态 → 用 `Program.s` 全局变量。
- 按钮发命令用 `printh NN`（十六进制，1 字节）。

### 2.5 其他

- 改任何源文件**先备份**；批量替换前先全量扫描列出待改清单，按**多维度**（外设名 + 引脚名 + 波特率 + 变量名）扫描，单维度必漏。
- 声称"改完"前必须给出**可复核证据**（编译日志 / 字节级比对 / 工具校验输出）。
- 生产环境（106.54.229.143）操作须先确认，默认只在本地验证。
- 硬件：BOOT0 必须拉低接 GND；SWD 必须接 RESET 引脚。

## 4. 系统要点（下一任必须知道的机制）

### 4.1 链路

| 链路 | 外设 | 引脚 | 参数 |
|---|---|---|---|
| MCU ↔ 屏 | **USART3** | PB10(TX)/PB11(RX) | 9600 8N1，RX 中断（单字节） |
| MCU ↔ 传感器 | **UART4** | PC10/PC11 | 9600 8N1（**在 `BSP/Src/sensor.c` 手工配置，不在 `.ioc`**） |
| MCU ↔ Flash | SPI1 | SCK=PA5/MISO=PA6/MOSI=PA7/CS=PA4 | W25Q64 |
| 电池 | ADC1_IN9 | PB1 | 分压 R22=100k / R23=24k |

### 4.2 协议单一事实源：`Middleware/Inc/c4f7n_hmi_protocol.h`

屏 → MCU 命令码（`printh NN`，单字节）：

| 码 | 宏 | 含义 |
|---|---|---|
| `0x01` | `HMI_CMD_PEAK_RESET` | 峰值复位 |
| `0x11`/`0x12` | `THR_HI`/`THR_LO` | 阈值回读触发 |
| `0x13`/`0x14` | `UNIT_TOG`/`BUZ_TOG` | 单位 / 蜂鸣开关 |
| `0x15`/`0x16`/`0x17` | `CAL_ZERO`/`CAL_SPAN`/`CAL_FAC` | 零点 / 量程标定 / 恢复出厂 |
| `0x18` | `PUMP_TOG` | 泵 / 测试启停 |
| `0x21`/`0x22` | `VIEW_CURVE`/`VIEW_DATA` | 切曲线 / 数据表视图 |
| **`0x23`** | **`TBL_NEXT`** | 表**下一页** |
| `0x24` | `EXPORT` | 导出（当前 no-op） |
| **`0x25`** | **`TBL_PREV`** | 表**上一页** |
| `0x40`~`0x43` | `PAGE0..3_ENTER` | 进页通知（**MCU 实测收不到此事件**，见 §5.2） |

MCU → 屏：`obj.val=` / `obj.txt=` / `obj.pco=` / `obj.pic=` / `vis obj,N` / `page N` / `add` / `cls` / `dim=` / `play` / `get obj.prop`，逐条追加 `FF FF FF` 帧尾（`tjc_cmd.c`）。

回读应答帧格式（`hmi_get.c`）：数值 `0x70 + 4B 小端 + FF FF FF`；字符串 `0x71 + ... + FF FF FF`。

### 4.3 历史存储

- 记录 **6 字节**：`u32 时间戳(秒，大端)` + `u16 ppm`；每扇区 682 点（`(4096-4)/6`）。
- `HIST_PERIOD_MS = 1000`（约 1s 落盘，**且仅在"测试中" `g_test=1` 时写**）。
- `HIST_SECTORS = 2047`（W25Q64 8MB，扇区 0 存参数，扇区 1~2047 为环形历史）。
- **`HIST_TBL_ROWS = 24`**（表格每页 24 条，屏上为**左右双栏**各 12 行）。
- `history_read_page()` 返回第 0 行 = **最新**记录，逐行向更早。
- 时间基准：`wall_time_seconds()` → `rtc_wall_seconds()`（屏 RTC 校时 epoch + `HAL_GetTick` 补偿）。

### 4.4 主循环

`main()` → `while(1){ iwdg_feed(); app_refresh(); HAL_Delay(250); }`

`app_refresh()`（250ms，见 `Core/Src/main.c`）依次：校时轮询 `rtc_time_sync_poll()` → 探头/泵状态文案 → 电池 → 读浓度/峰值/谷值 → 平滑平均 → 报警判定 + 蜂鸣 → **每 1s 落盘历史** → **每 2s 无条件 `refill_table()`** → 主页各项写屏。

### 4.5 传感器（GC5G1）当前实现

- **文本行协议**（非二进制）：`BSP/Src/sensor.c` 的行缓冲 + `parse_frame()` 要求行形如 `[空白] 数字 [空白] "ppm"`，大小写不敏感、忽略 `\r`；数值用手写整数+小数解析（规避 `strtod` 在该工具链返回 0）。
- `SENSOR_FS_PPM = 1500.0f`（`BSP/Inc/sensor.h`），超量程不封顶，`g_ppm > SENSOR_FS_PPM` 判为报警等级 3。
- ⚠️ `sensor.h` 中 `SENSOR_FRM_HEAD0/HEAD1`、`SENSOR_PPM_OFFSET` 为**已废弃的二进制帧宏**，解析逻辑不再使用，勿误判协议。
- UART4 在 `sensor.c` 手工配置（含 `__HAL_RCC_UART4_CLK_ENABLE`），**不在 `.ioc`**；STM32F1 的宏名是 `UART4`（不是 `USART4`）。
- 🟡 **未经真机验证**（最高风险项）。

## 5. 本轮修复（2026-09-18）

### 5.1 历史表左右两栏顺序错乱

- **现象**：左列序号 1,3,5,7,9,11…，右列 2,4,6,8,10…；期望左列自上而下第 1–12 条、右列第 13–24 条。
- **根因**：屏端历史页版面是**行优先双栏**——对象下标 **偶 = 左列**、**奇 = 右列**，行号 = 下标 / 2（`tt0`(78,172) 左列第 0 行、`tt1`(438,172) 右列第 0 行、`tt2`(78,198) 左列第 1 行 …）。固件原来把记录序 `i` 直接当对象下标用，于是左列拿到的都是偶数序记录。
- **改动**：[main.c L634](file:///d:/Demo/C4jly/C4F7N_Demo/Core/Src/main.c#L634) 增加下标重映射 `i<12 → 2i`（左列）、`i≥12 → 2(i−12)+1`（右列）。
- **证据**：编译 0 Error / 0 Warning，Code 32150 → 32214。

### 5.2 历史表时间列恒为 `1970-01-01 00:0X:XX`

- **根因**：`g_wall_epoch` 恒为 0，`rtc_wall_seconds()` 退化成「开机秒数」，落盘时间戳即为 1970 + 开机时长的表现。而校时之所以拿不到时间：原实现**只在开机瞬间发起一轮、2 秒总超时后永久放弃**；屏端此刻常未启动或时间镜像尚未刷新 → 一次失败即永远 1970。
- **改动**：[main.c L159](file:///d:/Demo/C4jly/C4F7N_Demo/Core/Src/main.c#L159)、[L230](file:///d:/Demo/C4jly/C4F7N_Demo/Core/Src/main.c#L230) 改为三阶段状态机：
  1. **秒值活性探测**：读一次 `rsec`，等 1.2s 再读一次，值必须变化 → 排除屏端未启动时的"设计初值"；
  2. **读 6 项镜像** `rY/rM/rD/rH/rMi/rsec`；
  3. **合理性校验**（年 2020–2099、月 1–12、日 1–31）+ **失败无限重试**（屏端就绪后自动完成，无需重启）。
- **为什么必须做活性探测**：v4 屏端这些镜像对象有**设计初值 `2026-01-01 00:00:00`**（`rY=2026, rM=1, rD=1, rH=0, rMi=0, rsec=0`），数值完全合法，光靠范围校验会**误采信为有效时间**。
- **重要遗留**：**此前已落盘的旧记录时间列仍显示 1970**——它们写入时校时尚未成功，无法追溯修正，只能被新记录逐步覆盖。若需彻底清空，可格式化历史区（`HIST_SECTORS` 区域）后重新测量。

涉及的关键屏端事实（已实测）：

| 项 | 事实 |
|---|---|
| 秒镜像对象名 | **`rsec`**（不是 `ss`） |
| 镜像对象类型 | `type=54` 数字组件，`val` 属性有效（`get rY.val` 正确） |

### 5.5 二轮修复（真机验证后暴露的问题）

> 一轮 3 项烧录后**经真机确认生效**（时间列已能显示屏端实时时间），同时暴露出以下 3 个新问题。

**① 序号列翻页后不随页码变化**（`C4F7N_Demo/Core/Src/main.c` 的 `refill_table()`）

- **现象**：手动翻页后，序号列仍是"最新一组"的号，而时间/浓度列已按页更新 → 三列错位。
- **根因**：`recnum = total - i` 中的 `i` 只是**页内行号**（0..23），不含页码偏移。于是每页都从 `total` 重新起算，序号永远停在最新那 24 条。
- **改动**：`gi = (page-1) * HIST_TBL_ROWS + i`，`recnum = total - gi`。
- **数值校验**（每页 24 条 / 共 48 条）：修复前第 2 页序号与第 1 页**完全相同**（精确复现用户现象）；修复后两页连续递减、覆盖 1..48 无重复无缺失（断言 PASS）。

**② `pg` 跨页重名**

- **现象/根因**：全库扫描确认 —— 主页 `pg`（x=40 y=110 **930×40**）实为**顶部标题横幅**（文本 `C4F7N · 全氟异丁腈`），历史页 `pg`（x=640 y=474 110×24）才是页码。`refill_table()` 每 2s 无条件写 `pg.txt`，切到主页时就把标题横幅改成了页码（这是"每 2s 无条件重绘"改动暴露出的必然结果）。
- **改动**：`4.pa` 的横幅改名 **`ptitle`**（改名前校验：该名全库不存在、两页脚本均未引用 `pg`），历史页页码仍叫 `pg`，**固件与协议头无需改名**。
- **复查**：固件每 2s 无条件写入的全部名字（`tt0..23`/`np0..23`/`sn0..23`/`pg`/`mx`/`av`/`mn`/`du`/`ct`）现已**零重名**。

**③ 重启后历史表全空**（`C4F7N_Demo/BSP/Src/history.c` 的 `history_init()`）

- **根因**：`g_written` 是纯 RAM 变量，上电须靠扫扇区 head（代数 `seq`）重建。而 `if (h != SEQ_EMPTY && h > maxhead) { …; found = 1; }` 把"是否已有数据"与"哪个扇区最新"合并成了一个比较：首个环形扇区 `seq = 0`，而 `maxhead` 初值也是 0 → `0 > 0` 不成立 → 被判"无数据" → `g_written = 0` → `available = 0` → 表格全空。
- **自锁性**：一旦恢复成 0，下轮又从 `idx=0` 写同一扇区，`seq` 恒为 0 → **重启后永远读不到数据**，且每轮都就地覆写上一次的数据。**触发条件：累计记录 < `HIST_CAP`(682，约 11 分钟采样)** —— 日常短测试必然命中。⚠️ 该缺陷在 v5/v6 等**此前所有版本中同样存在**，非本轮引入。
- **改动**：`if (h != SEQ_EMPTY) { if (!found || h > maxhead) maxhead = h; found = 1; }`。
- **模型验证**（精确复刻 `history_log()` / `history_init()`）：写入 100 条 → 原实现恢复 0（❌ 全空）/ 修复版 100（✓）；700、1500 条 → 两者一致（无回归）。

**二轮产物与证据**：固件 `C4F7N_v7_firmware.hex`（AC6 **0 Error / 0 Warning**，Code=32234，与 v6 差 149 字节）；屏工程 `C4F7N_v4_fix2.HMI`（`RESULT: opens, 65 resources`、6 页 `check=33 OK`、`pages ok=6 bad=0`；回读确认 `p2R h=384 endy=467`、`pg` 仅在 `0.pa`、`ptitle` 仅在 `4.pa`）。
**编码安全**：`history.c` 是 **UTF-8**（非 GBK），故用 UTF-8 补丁，并做"非 ASCII 投影多重集合"校验 → **原有中文行零丢失**、严格 UTF-8 有效。
**✅ 二轮 3 项已于 2026-09-18 真机验证通过。** 烧 `C4F7N_v7_firmware.hex` + `C4F7N_v4_fix2.HMI` 后逐项确认：翻页后序号随时间/浓度一致变更、主页标题横幅不再被页码覆盖、**断电重启后仍能显示重启前的历史**（序号从上次编号继续，不再从 0001 重来）。
