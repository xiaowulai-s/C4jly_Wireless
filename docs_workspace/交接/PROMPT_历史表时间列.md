## 3. 为什么会出现"1970"

`g_wall_epoch` 恒为 0 时，`rtc_wall_seconds()` 退化为"开机秒数"，落盘时间戳即 1970-01-01 + uptime。
原实现的根因是**只在开机瞬间跑一轮校时、2 秒超时即永久放弃**，而屏端此时往往尚未启动或时间镜像未刷新 → 一次失败即永远 1970。

现改为三阶段状态机 `g_sync_st`：

1. **秒值活性探测** —— 读一次 `rsec`，等 1.2s 再读一次，秒值必须变化；
   必要性：屏端镜像对象带**设计初值 `2026-01-01 00:00:00`**，数值合法，光靠范围校验会误采信。
2. **读 6 项镜像** `rY/rM/rD/rH/rMi/rsec`。
3. **合理性校验**（年 2020–2099、月 1–12、日 1–31）+ **失败无限重试**（屏端就绪后自动完成，无需重启）。

## 4. 屏端已实测事实（勿再重复侦测）

| 项 | 事实 |
|---|---|
| 秒镜像对象名 | **`rsec`**（**不是** `ss`） |
| 镜像对象类型 | `type=54` 数字组件，`val` 属性有效（`get rY.val` 正确） |
| 刷新者 | 页内 `tm0` 定时器，`tim=300`(ms)、`en=1`，脚本 `rY.val=rtc0 … rsec.val=rtc5` |
| 哪些页刷镜像 | `0/1/3/4/5.pa` 都刷；**只有 `2.pa`（`keybdB` 键盘页）不刷**（其 `tm0` 只切换 `tm0.tim`） |
| 设计初值 | `rY=2026, rM=1, rD=1, rH=0, rMi=0, rsec=0` → `2026-01-01 00:00:00`（活性探测存在的原因） |

## 5. 若仍需继续处理，剩余方向

1. **旧记录 1970**：三选一 —— ① 接受现状等新记录覆盖（零风险）；② 显示层兜底（`ts < 1577836800` = 2020-01-01 时显示 `未校时`/`----`，非破坏性，**推荐**）；③ 擦除历史环形区（扇区 1~2047，**会丢数据，须用户确认**）。
2. **±1 秒精度**：读 6 项之前与之后各读一次 `rsec`，两次不同则整轮重读，保证同一秒内取值。
3. **长期漂移**：目前只在开机校时一次，之后纯靠 `HAL_GetTick`；可改为每隔 N 分钟重新校时（屏端 RTC 有电池保持走时），把漂移限制在 N 分钟内。

> 以上 3 项均**未被要求实施**，如需推进请先与用户确认。
