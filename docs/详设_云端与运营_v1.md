## 三、SyncAdapter 接口定义（第一代落位到 App）

```dart
abstract class SyncAdapter {
  /// 幂等上行：按 (sn, task_id) 去重；断网进入待发队列
  Future<void> pushTasks(List<Map<String, Object?>> tasks);
  Future<void> pushEvents(List<Map<String, Object?>> events);
  Future<void> pushHeartbeat(DeviceStatus s);        // SN/电量/版本/告警态
  Future<FwInfo?> checkFirmware(String sn, String curVer);
  Future<ActInfo?> checkActivation(String sn);
  Future<List<ParamPatch>> fetchRemoteParams(String sn); // 远程调参（谨慎）
}
```

- 数据格式：JSON（字段名与协议 param_id 对齐），SN 为主键之一；
- 队列：本地 `pending_sync` 表，失败静默重试（退避），永不阻塞业务；
- 隐私边界：位置/报告默认**不上传**（仅用户显式分享时走导出文件）。

## 四、售后远程支持分层（F6）

### 第一代（离线诊断包，第一代末实现）
1. PC"提取诊断包"：SN + 固件版本 + param 全表 + 维护计数 + 最近事件 → JSON 文件；
2. 微信/邮件发给厂家 → PC"导入分析"：参数比对标准值 + 异常标注；
3. 修复动作：厂家给出 param 补丁文件 → PC"应用补丁"经 BLE 写回（厂家会话）。

### 第二代（在线）
1. 设备经用户手机 App 心跳上行（错误码/维护计数/版本）；
2. 厂家后台：设备档案页（激活状态/保修期/最近告警）+ 远程读参/推参（需设备在线且用户确认）；
3. 通道选型候选：自有服务器（完全掌控）/ 微信小程序 + 云开发（客户触达好）/ MQTT 直连（设备直上，绕过手机）——R4 按商业化需要决策。

## 五、授权/激活机制设计（F5，第一代离线实现）

```
激活码 = Base32( AES/异或派生( SN 规范化 + 设备类型码, 厂家私钥派生流 ) + CRC )
校验（设备内/手机内，离线）：
  1. 解码 → 取出 SN 与校验和
  2. SN 与本机 device_id 比对
  3. CRC 通过 → 写激活标志（device_id 页扩展记录，同页共管模式）
```
- 试用策略：首次上电起 30 天全功能，到期后**测量不受限**、报告导出受限（商业策略可调）；
- 激活码生成器放厂家侧（PC 产测工具或独立小工具），私钥不入固件明文——固件只存派生校验参数；
- 经销商模式（未来）：经销商码批量激活 → 云端登记归属，为看板数据做准备。

## 六、OTA 分发（F4 第二代部分）

- 固件包格式：`{target: esp32|stm32, version, sha256, signature, bin}`；
- 分发：云端按 SN/机型下发清单 → App/PC 提示更新 → 经 BLE/USB-CDC 执行 0x70 命令族；
- 灰度：按 SN 白名单先行。
