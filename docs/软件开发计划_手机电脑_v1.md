## 二、手机 App（第 1~2 周为主线）

### 1. 多设备管理（切换式）
- 扫描列表支持多设备收藏（本地持久化：名称/SN/最近连接时间）；
- 连接模型：**同时仅 1 台在线**，列表一键切换（断旧连新，2s 内完成）；
- 任务/事件按设备 SN 归档（TaskStore 增加设备维度查询）。
- 工作量：~2 天。

### 2. 报警通知提醒
- Android **前台服务（Foreground Service）+ 常驻通知**：后台/锁屏期间保持 BLE 扫描连接与报警判断（Android 12+ 需 `FOREGROUND_SERVICE` + `POST_NOTIFICATIONS` 权限引导）；
- 报警触发 → 系统级高优先级通知（声音+振动，绕过勿扰可选）；
- 与切换式多设备组合：通知中携带设备名，点击跳转对应会话。
- 工作量：~2.5 天（含真机功耗观察）。

### 3. 报告/导出增强
- 任务报告新增 **Excel 导出**（`excel` 包：曲线数据 sheet + 汇总 sheet）；
- **多任务汇总页**：按时间/设备筛选，统计总任务数/报警次数/超标时长，可整批导出；
- PDF 模板微调（封面 SN、阈值、报告编号规则 `R+YYYYMMDD+任务号`）。
- 工作量：~2 天。

### 4. 体验细节打磨（清单驱动）
- 曲线支持双指缩放/长按查看数值；深色模式；首次使用引导页；连接中/无响应/权限拒绝三态文案统一；错误页恢复按钮。
- 工作量：~2 天（清单滚动）。

### 5. 真机联调收口（M1，穿插进行）
- STM32 烧 hex → USART2 接线 → 全链路 10 项走查（验证流程文档 §B2）；
- 联调暴露的问题当日修复当日重出包。

## 三、电脑端产测工具（第 1~3 周主线）

### 技术底座
- **Tauri 2 + React 19 + TypeScript 前端；Rust 后端**；
- BLE：`btleplug` crate（Windows 成熟支持），协议复用 `packages/c4f7n_protocol`（Dart 包导出 TS/JSON 描述 + Rust 端重实现编解码，二选一：**选 Rust 重实现**，单元测试对照 Dart 测试向量冻结）；
- 本地库：SQLite（sqlx/rusqlite）存产测记录。

### 功能拆解
| 功能 | 说明 | 依赖 |
|---|---|---|
| 1. 连接与状态 | 扫描/连接 C4F7N-*、MTU、心跳、断线重连、设备信息卡 | btleplug |
| 2. 基础厂家功能 | 口令登录（0x7A）、手动补偿 b/k（0x31 含 20% 确认）、标定、自检、恢复出厂 | 协议 Rust 版 |
| 3. 一键产测流程 | 向导式：上电自检→零点校准→示值核对（人工注入标准气，记录偏差）→阈值写入→**产测报告（合格/不合格自动判定）** | 1+2 |
| 4. SN 烧写绑定 | 读当前 SN → 写新 SN（协议 v1.1 新命令）→ ESP32 广播名联动 → 校验回读 | M4 协议扩展 |
| 5. 产测记录台账 | 每次产测入库（SN/时间/各项结果/判定/操作员备注）；按 SN/日期检索；导出 Excel | 3 |

### USB-CDC（下一期预留）
- 本期只做 BLE；ESP32 固件加 TinyUSB CDC 数据通道作为下一期任务（接口层预留 `Transport` trait，BLE/USB 双实现）。

## 四、协议 v1.1 扩展（M4，第 3 周）

- 新增维护命令族 **0x00**：`0x0001 SN 读取`（免会话）、`0x0002 SN 写入`（需厂家会话 + confirm，写入 STM32 内部 Flash 最后一页 device_id 区，含 CRC 校验与回读验证）；
- SN 变更后：param 0x0008 设备编号联动、ESP32 广播名联动（ESP32 收到 param 变更事件或重启生效）；
- STM32 侧：device_id 写入函数 + wireless.c 分发扩展；ESP32 侧无需改动（透传）；
- 同步去认证旁路：product_info.h 烧写 `PRODUCT_FACTORY_DIGEST`，`WL_FACTORY_AUTH_BYPASS=0`；
- 三份文档同步升版（协议 v1.1、进度表、验证流程）。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| Android 后台限制杀前台服务 | 前台服务+电池优化白名单引导；提供"保持后台监测"开关说明页 |
| btleplug Windows BLE 兼容性差异（不同蓝牙适配器） | 第 1 周先做连接冒烟验证；产线环境固定适配器型号 |
| SN 写入 Flash 的安全性（写坏变砖） | 仅厂家会话可写；写入前双重确认；CRC+回读校验；保留原 SN 备份记录 |
| 多设备切换时心跳/订阅状态残留 | 切换即完整 teardown 重建（沿用现断线清理逻辑） |
| 两端并行人力切换成本 | 协议/数据层先行冻结，UI 层两端独立推进 |

## 七、本计划依赖的即时行动

1. **M1 联调**：本周内 STM32 上电接线（GPIO17→PA3、GPIO18→PA2、共地）；
2. 确认产测工具运行环境：产线电脑为 Windows（建议 Win10+，蓝牙适配器型号待定）；
3. 现有 ESP32 开发板继续留作 App 真机验证的"移动测试台"。
