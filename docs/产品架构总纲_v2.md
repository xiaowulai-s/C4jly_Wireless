## 三、模块间关联（数据流）

1. **设备 ⇄ 手机 App**：BLE（ESP32 GATT）→ 协议 v1.1 帧 → STM32 分发；手机发起全部请求-响应；设备 1Hz 主动推 0x10 实时帧、0x60 事件帧。
2. **设备 ⇄ PC 产测**：同一条 BLE 通道（同一协议）；后继 USB-CDC 同协议（Transport 抽象）。**互斥**：设备单连接，手机与 PC 不能同时连。
3. **App ⇄ 云端**：本地 SQLite → SyncAdapter 接口（上传任务/事件/设备心跳，下拉固件版本/授权状态）。第一代不实现，数据模型已含同步所需字段（id/时间戳/SN）。
4. **PC ⇄ 云端**：产测台账 → 批量导出 →（未来）产线 MES/证书服务。
5. **设备自治原则**：报警判断、蜂鸣、泵保护、参数持久化全部在 STM32；任何手机/PC 断线不影响检测与报警——这是对外交付的可靠性底线。

## 四、本轮新增推荐功能（已确认方向，按依赖排序）

### F1 · 维护与耗材管理（M1 数据源 + M2 展示 + M5 提醒）
- 设备端新增维护参数（param v1.2）：`累计运行小时`、`累计报警次数`、`传感器累计通电时长`、`电池循环/健康估计`、`滤芯状态`（如有）；
- 手机 App 维护页：显示各项 + 到期阈值（param 可配）→ 本地通知提醒；
- PC 端产测/售后可读写维护计数（重置需厂家会话）。

### F2 · 计量合规与出厂证书（M3 出 + M1 数据支撑）
- 产测合格 → PC 自动生成**出厂标定证书 PDF**（SN/日期/标定点/示值误差/操作员/有效限期）；
- 设备端新增 `证书数据块`（标定日期、标定值、证书编号）——即现有 `cal_ts/cal_k/cal_b` 已有一半，补证书编号与有效期字段；
- 年检提醒：App 读取证书日期 + 有效期（默认 1 年）→ 到期提醒 + 年检流程引导（复用零点/标定向导）。

### F3 · 泄漏点地图/台账（M2 为主）
- 任务元数据扩展：`site` 已有 → 新增 `geo_lat/geo_lng`（手机定位自动填充）+ `pipe_section`；
- App 新增地图页：任务/事件按位置呈现（第一代可用静态图/列表定位，后续接入地图 SDK）；
- 报告自动携带位置信息。

### F4 · OTA 升级体系（M1 分区 + M2/M3 触发 + M5 分发）
- 协议 v1.2 定义 0x70 命令族：`0x70 查询版本/分区状态`、`0x71 传输固件块`、`0x72 校验+切换`；
- ESP32 OTA：官方分区方案（factory + ota_0/ota_1 已预留），PC/手机经 BLE 推流；
- STM32 OTA：经 ESP32 转发写外部 W25Q64 暂存区 → 校验 → Bootloader 切换（需 Bootloader 支持，工作量最大，放 R3）；
- 安全：固件包带版本号+SHA256+厂家签名（会话内才可 OTA）。

### F5 · 授权/激活机制（外部客户场景）
- 设备首次开机进入**试用期**（如 30 天全功能）→ App 输入激活码（离线算法：SN+密钥派生，可离线校验）→ 永久激活；
- 激活状态存 device_id 页（与 SN/认证哈希同页共管，已有机制复用）；
- 订阅制/分期功能授权留到云端第二代。

### F6 · 售后与远程支持（分层实现）
- 第一代（离线）：PC 端"**诊断包**"一键导出（SN+固件版本+参数区+维护计数+最近事件）→ 微信发给厂家 → 厂家用 PC 工具"导入诊断包"分析；
- 第二代（在线）：设备经用户手机上传心跳/错误日志到云端，厂家后台远程读参/推修复。

### F7 · 上手难度（外部客户）
- App 引导页已就绪，增补：演示模式（Mock 数据源一键开启）+ FAQ 页 + 常见问题自查（连接失败自查表）+ 售后入口（电话/微信按钮）；
- 设备端出厂默认参数调至"开箱即用"（阈值/泵自动策略）。

### F8 · 标定参数防提取（外部客户场景）
- param 区标定参数（cal_k/cal_b/man_k/man_b）读写加厂家会话门槛：普通会话只读"补偿后示值"，不可读原始 b/k；
- 认证哈希机制已就绪（v1.1），量产关闭 BYPASS 即生效。

## 五、安全与权限模型（贯穿三端）

| 层级 | 权限 | 获得方式 |
|---|---|---|
| L0 匿名（免会话） | 实时数据、心跳、SN 读取、版本查询 | 连接即有 |
| L1 用户操作 | 泵/静音/阈值写、零点校准、历史读取 | 连接即有 |
| L2 厂家会话 | 标定/补偿写入、SN 烧写、认证哈希烧写、OTA、维护计数重置、恢复出厂 | 0x7A 认证（SHA-256 口令比对，5 次锁定） |
| L3 产线物理 | 引导区/Bootloader 写入 | 需物理接触（SWD/USB DFU），不开放远程 |

## 七、风险与开放问题

1. **量产认证链**：BYPASS 关闭依赖 0x00/0x03 烧写哈希——必须在产测流程（PC 一键产测）里固化"烧写认证哈希"步骤，避免出厂漏烧导致设备锁死；
2. **OTA 对 STM32**：外部 Flash 暂存 + Bootloader 切换是 R3 最大工作量项，建议 ESP32 OTA 先行验证流程；
3. **地图 SDK 成本**：泄漏地图第二代若商用地图（高德/腾讯）需 Key 与合规，第一代用离线/系统分享替代；
4. **多机同区协同**：手机 BLE 单连接限制，多机需"轮询切换"或设备侧组网（LoRa/总线），属于 R4+ 架构决策；
5. **云接口抽象**：SyncAdapter 先定义接口与本地 mock 实现，云端供应商（自有服务器/微信生态）R4 再选型。
