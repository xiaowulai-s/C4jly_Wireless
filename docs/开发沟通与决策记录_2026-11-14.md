## 三、关键技术决策记录（DR 摘录）

| DR | 决策 | 理由 |
|---|---|---|
| DR-1 | ESP32 仅透传，业务全在 STM32 | 屏版逻辑平移成本最低；ESP32 固件极简稳定 |
| DR-2 | 协议 v1 一次冻结 + 三方互验测试向量 | 避免三方各自理解漂移；CRC 实算值写入文档 |
| DR-3 | 模拟器 App 顶真机先行 | 硬件未到不阻塞 App 全部开发 |
| DR-4 | 协议包独立（纯 Dart） | App/模拟器/PC 三端共用一份编解码 |
| DR-5 | Mock/Ble 数据源抽象 | 无硬件体验 + 真机切换零改动 |
| DR-6 | ESP32 接线 USART2 而非 USART1 | USART1 是 devtest 调试口（R4 实锤） |
| DR-7 | USART2 用 DMA 循环 RX + 轮询 NDTR | main.c 的 `HAL_UART_RxCpltCallback` 只服务 USART3，中断会打架 |
| DR-8 | main.c 补丁走 GBK 安全脚本 + 唯一锚点 | 项目 GBK/LF 纪律，杜绝编码损坏 |
| DR-9 | 设备名入 Scan Response | 广播包 31B 上限（真机实测踩坑后固化） |
| DR-10 | 厂家认证烧录期旁路（BYPASS=1） | 桌面联调不卡认证；量产前烧写摘要并关闭（遗留 R-1） |

## 四、问题与修复档案

| # | 现象 | 根因 | 修复 | 状态 |
|---|---|---|---|---|
| B1 | 开泵后关不掉 | `togglePump` 把"命令成功"误当"设备状态"赋值；Mock 恒返回 true | `setPump/setMute` 统一语义为"返回设备实际状态（ACK 回显）"；静音占位逻辑一并修复 | ✅ |
| B2 | 协议测试向量帧3/帧4 CRC 对不上 | 手算向量字节序错误（版本号误用大端、thr 字节写错） | 按小端重算并回写协议 v1.md；Dart 实现验证一致 | ✅ |
| B3 | buildFrame/tryParseFrame 缓冲区少 1 字节 | 分配 `4+len` 应为 `5+len`（head2+len1+body+crc2） | 修正两处；极限帧测试覆盖 | ✅ |
| B4 | sdkmanager 卡死 20 分钟 | 许可协议交互确认 | 先 `yes \| sdkmanager --licenses` | ✅ |
| B5 | Gradle zip 损坏 / 下载失败 | 国内网络 + wrapper 残留 | 腾讯镜像手动下载校验 → 放 `~/.gradle/wrapper/dists/<hash>/`；settings.gradle.kts 加阿里云镜像 | ✅ |
| B6 | Kotlin 增量缓存关闭失败 | 首编中断残留 | `kotlin.incremental=false` | ✅ |
| B7 | ESP32 编译五连败 | pyvenv.cfg 残留 D 盘路径 / ESP_ROM_ELF_DIR 缺失 / idf.py 拒绝 MSYS / IDF 仓库 `bootloader/Kconfig.log` 被删 | 逐项修复（git restore 恢复框架文件） | ✅ |
| B8 | ESP32 广播不工作（`adv_set_fields rc=4`） | 广播载荷 32B 超 31B 上限 | 设备名移入 Scan Response | ✅（真机验证） |
| B9 | App"连接 2 秒失败"（假象） | 连接后读阈值 2s 超时（裸 ESP32 无应答方），App 误标连接失败 | 阈值读取失败保持连接 + 明确提示；泵/静音/阈值操作加无响应提示 | ✅ |
| B10 | 连接后绑定存储报 `status=8`（部分手机踢连接） | NimBLE 缺 `ble_store_config_init()` 调用 | 补调用（该版本无头文件声明，手工 extern） | ✅（真机验证） |
| B11 | UV4.exe 被系统禁用（旧记录） | Keil 从 D:\KEIL 迁移至 C:\Software\KeilC51 | 迁移后禁令自然失效；node spawnSync shell:true 调用成功 | ✅ |

## 五、真机验证实录（ESP32-S3，2026-11-14 夜）

- 板卡：b8:f8:62:e5:03:08（Flash 实际 16MB，镜像按 8MB 配置——无碍，后续按板型调整）；
- 烧录：COM5，USB-Serial-JTAG 免驱动，460800 baud；
- 启动日志确认：`C4F7N bridge up` → `stack synced, advertising as C4F7N-0001` → `GAP procedure initiated: advertise`；
- 连接日志确认：`phone connected, conn=1` → `mtu=517`（优于预期 247）→ `notify sub=1` → 链路稳定保持；
- 已知良性告警：`Failed to restore IRKs status=8`（已由 B10 根治）、`Flash 16MB > header 8MB`。
